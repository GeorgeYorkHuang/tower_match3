# R14第二批：圣遗物波次触发拆分

## 接口与所有权

`js/relics/wave-hooks.js`导出三个函数，均显式接收Run，不缓存玩家、Meta或Enemy引用：

- `startWave(run)`：战术转移每波免费洗牌；记录波初城墙血；赏金猎人连续无宝箱计数；清除本波已掉箱标记。
- `endWave(run)`：金库波末银币加成与3★无伤额外30%；生命回复与3★溢出护盾，护盾保持10%最大血量上限。
- `bountyGuarantee(run)`：保留原3★、连续计数阈值判断，成功消费后清零。

Run原startWave/endWave/bountyGuarantee方法名和返回值保留。Config仅提供共享定义；freeShuffle、_bountyStreak、_waveChestDropped、_waveStartHp、gold、lineHp、wallShield都属于当次Run。

## 保持原顺序

波初：wave递增 → 全局技能护盾重置 → 战场风场/诅咒叠层 → 圣遗物波初触发 → 计算本波基础银币。

波末：金库银币与无伤判定 → 回血/溢出护盾 → 计算敌人血量及DPS → 模拟路径漏怪扣血（真实路径skipLeak）→ 协同/破防与波次上限判定。

保底仍由精英掉落处按原逻辑调用，随机成功时短路，不额外消费保底。本批不重解释“连续三波”的原计数时点，不改变重复调用的原有语义，也不新增幂等或奖励规则。基础波次推进、主流程经验、撤离点、深度收益及全局技能状态不迁移。
