| # | 结论 | 关键证据 |

## 1. 分析方法与口径

### 1.1 三条曲线的定义

| 曲线 | 度量 | 来源 |
|---|---|---|
| 升级速度 | 经验等级 `expLevel`、塔级和、每波升级所需波数 | `js/run.js` `gainExp`/`expNeed`、`js/config.js` `EXP` |
| 技能强度 | 技能乘区 `skillMult = totalDps / Σ(baseDps + perLv×(L−1))`、激活技能数、分支等级和 | `js/effects.js` `TowerBuild.dps()`、`js/config/skills.js` `EFFECT` |
| 怪物强度 | 逐波有效血量 `effHp = Σ hp/(1−armor)`、攻城 DPS、数量、主等级 | `js/config/monsters.js` `levelOf/levelMix/mainLevel/waveTotalHp`、`js/config/enemy-balance.js` |
| Boss 强度 | 脚本 Boss 波（20/40/60）逐项精算投放血量 | `js/config/bosses.js` + `js/bosses/{rosea,galvin,vera}.js` 的 `enemyTotalHp` |

### 1.2 难度指标

```
需求 demand = effHp = Σ 每只怪 hp / (1 − min(armor, 0.85))
供给 supply = totalDps × WAVE.seconds(40) / windMul
压力 pressure = demand / supply        # 1.0 = 恰好 40 秒清完
缺口 leak   = max(0, demand − supply)  # 与 run.endWave() 的 leak 同口径
```

`pressure > 1` 表示该波在 40 秒内清不完，差额转城墙伤害。城墙初始 `CONFIG.LINE.hp = 2000`。

### 1.3 两种经验口径（并行对照）

| 口径 | 经验来源 | 说明 |
|---|---|---|
| `sim` | 仅三消经验 | 项目自带 `Run.simulateRun` 的口径，是**成长下界** |
| `real` | 三消 + 击杀经验（按本波击杀完成度折算）+ 波末经验 `waveBonus × 已获得塔数` | 补全真实游戏链路（`js/game/main.js:607`），本文**默认用此口径** |

W60 总 DPS：`sim` 287 vs `real` 510，相差 1.78×。两者结论方向一致，仅失衡幅度不同。

### 1.4 模拟设置

- 20 组固定种子（`20261109 + s × 7919`），逐波均值；波次范围 W1–W60，每波 5 次消除，形状/颜色抽样与 `Run.simulateRun` 完全一致。
- `endWave(true)` 采用 `skipLeak` 诊断模式，不扣城墙血，以便观察完整 60 波而非中途 game over。
- 修正项：项目自带模拟器在中后期会崩（`EffectManager` 持有 rng，但 `TowerBuild.pickChoices()` 直接调 `this.rng()`）。分析脚本仅**只读注入** rng，不修改任何游戏代码。
- 普通波血量口径已与 `ENEMY.waveTotalHp` **逐波 1–60 全量校验一致**；三个脚本 Boss 波原始血量与各自 `setup()` 的 `enemyTotalHp` 完全对齐。

## 2. 数值口径还原

### 2.1 升级速度

```
expNeed(L) = EXP.base × EXP.growth^L = 35 × 1.25^L
```

| 常量 | 值 | | 常量 | 值 |
|---|---|---|---|---|
| `EXP.base` | 35 | | `EXP.growth` | 1.25 |
| `EXP.perCell` | 2 | | `towerMaxLevel` | 13 |
| `EXP.shape` | 3消×1 / 4消×1.5 / 5消×2 / L5×1.5 / 6+×2.5 | | `waveBonus` | 5 / 塔 |
| `EXP.kill` | normal 15、runner 10、tank 22、elite 30、boss 90 | | `WAVE.matchesPerWave` | 5 |

| 经验等级 L | 0 | 5 | 10 | 20 | 30 | 40 | 48 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 升下一级需求 | 35 | 107 | 326 | 3,036 | 28,273 | 263,311 | 1,569,454 |

经验来源上限：4 塔槽 × (13−1) 次升级 = **理论 48 级**，对应需求已达 157 万；而单波经验供给量级仅数百。

### 2.2 技能强度

```
单塔 DPS = (baseDps + perLv×(L−1)) × Π_over_3_slots (1 + 0.15 × ef.level) × (1 + 0.5 if 协同)
```

| `EFFECT` 常量 | 值 |
|---|---|
| `activeSlots` / `maxLevel` / `pickSize` | 3 / 3 / 3 |
| `bonusPerLv` / `synergyBonus` | 0.15 / 0.5 |
| 理论最大乘区 | `(1+0.15×3)³ × 1.5 = 1.45³ × 1.5 =` **4.573** |
| 单塔 Lv13 线性 DPS（6 塔） | 118.4 / 97.9 / 109.4 / 110.4 / 101.0 / 124.8 |
| 4 塔 Lv13 线性合计（均值） | 441.2 |
| **理论满配总 DPS** | 441.2 × 4.573 ≈ **2,018** |

> 注：图表及早期草稿曾出现 6.14，那是按 `1.6³×1.5` 误算；配置实际为 `bonusPerLv=0.15`，已修正为 **4.573**。

### 2.3 怪物强度

- 等级表共 **14 级**，`mainLevel(w)` 分代推进，`levelMix(w)` 给出 5 项循环配置；`countForWave`：W1=15、W10=25、W20=39、W40=67、W60=95。
- 每 5 波一个小 Boss（`bossEvery=5`，`bossHpMult=8`、`bossArmor=+0.25`）；每 20 只怪 1 精英（`eliteHpMult=3`、`eliteArmor=+0.06`）。
- 护甲按 `hp/(1−armor)` 折算有效血量，上限截断 0.85。
- 战场被动：诅咒 `×1.15^n` 血量、风场 `/1.10^n` 有效输出时长（本次种子下影响很小）。
- 脚本 Boss 波 W20/40/60 的整波投放被 `Boss.setup` **重写**，不再走通用 `waveTotalHp`，故单独逐项精算。

## 4. 难度曲线与失衡拐点

### 4.1 阶段划分

| 阶段 | 波次 | 压力区间 | 特征 |
|---|---|---|---|
| 开局缺口 | W1 | 1.20 | 0 级、0 技能，首波即漏 516 |
| 舒适区 | W2–W6 | 0.51–0.92 | 经验需求低、升级快，玩家短暂领先 |
| **第一拐点** | **W7** | 1.16 起连续 8 波 >1 | 怪物代际（W6 mainLv3）超过成长速度 |
| 系统性缺口 | W10– | 1.62，除 W16–18 外再未回落 | 玩家 DPS 增速开始显著落后 |
| 平台期发散 | W25– | 4 ~ 26 | 玩家 DPS 几乎不动，怪物血量继续翻番 |
| Boss 断层 | W20 / 40 / 60 | 4.56 / 40.56 / 158.76 | 见 4.2 |

W1–W9 压力逐波：`1.20, 0.67, 0.51, 0.57, 0.82, 0.92, 1.16, 1.09, 1.26`

### 4.2 三个脚本 Boss 尖峰

| Boss 波 | 有效血量 | 相邻非 Boss 波均值 | 倍数 | 压力 | 相邻波跳变 |
|---:|---:|---:|---:|---:|---|
| W20 罗塞娅 | 73,955 | 38,751 | **1.91×** | 4.56 | W19→W20 ×3.00 |
| W40 迦尔文 | 746,990 | 185,784 | **4.02×** | 40.56 | W39→W40 ×4.17 |
| W60 薇拉 | 3,119,410 | 349,085 | **8.94×** | 158.76 | W59→W60 ×8.94 |

Boss 波次日立即回落：W40→W41 有效血量 ×0.26（74.7 万 → 19.2 万）。即难度曲线不是单调上升，而是「阶梯 + 孤立尖峰 + 回落」，尖峰倍率随波次放大。

> 三个脚本 Boss 的血量是**下界**：迦尔文共鸣回血、薇拉 ward 护甲递增与周期召唤均为动态增益，未计入静态投放表。

### 4.3 经验供需剪刀差

| 波 | 升下一级需求 | 击杀经验池 | 击杀完成度 | 单波经验供给(估) | 升一级需几波 |
|---:|---:|---:|---:|---:|---:|
| 1 | 35 | 225 | 0.87 | 250 | 0.1 |
| 5 | 261 | 332 | 1.00 | 387 | 0.7 |
| 10 | 685 | 510 | 0.64 | 381 | 1.8 |
| 15 | 1,169 | 510 | 0.69 | 408 | 2.9 |
| 20 | 1,651 | 305 | 0.23 | 124 | 13.3 |
| 30 | 2,113 | 870 | 0.25 | 273 | 7.7 |
| 40 | 2,581 | 728 | 0.03 | 74 | 35.1 |
| 50 | 3,226 | 1,330 | 0.08 | 161 | 20.0 |
| 60 | 3,226 | 960 | 0.01 | 61 | **52.6** |

**自我强化的死循环**：需求按 `1.25^L` 指数涨 → 供给主要来自击杀经验、按 `击杀完成度` 折算 → 打不过就漏怪、漏怪就少拿经验 → 升级更慢 → 更打不过。这是 W20 后成长彻底冻结的机制性原因。

### 4.4 攻城承压

满编怪同时抵达时的理论攻城 DPS：W1 120（2000 血撑 16.7 s）→ W25 922（2.2 s）→ W55 2,646（0.8 s）→ W60 1,773（1.1 s）。40 秒波次时长下，中后期城墙几乎没有容错窗口。注意这是**未计入冰墙、控制、减速、击杀削减**的理论满编值，仅作威胁度趋势参考。

### 4.5 代际锯齿（W42 后）

`mainLevel` 跃迁序列：`W42=10 → W44=11 → W45=10 → W46=11 → W49=12 → W50=11 → W51=12 → W54=13 → W55=12 → W56=13 → W59=14 → W60=13`。

主等级在相邻两级之间反复来回跳，`waveTotalHp` 随之震荡（W44 118,660 → W45 128,860 → W46 103,020）。表现为难度曲线非单调：W15→W16 ×0.69、W20→W21 ×0.72、W25→W26 ×0.76、W30→W31 ×0.78 等周期性回落。这类回落与玩家侧无关，纯由取表规则产生。

## 5. 核心失衡诊断

1. **成长封顶早于难度起跳。** 玩家侧四条指标（经验等级、塔级和、技能数、乘区）在 W20–25 全部进入平台，W50 后完全冻结；怪物侧按 14 级等级表持续推进到 W60。压力比因此从 W10 的 1.62 单调发散到 W60 的 158.76。
2. **理论满配不可达。** W60 达成度：经验等级 42%、塔级和 47%、技能乘区 46%、总 DPS **25%**。技能系统 3 槽 × 3 级 × 协同的设计空间只被用掉不到一半，问题不在技能强度上限，而在**没有足够的升级次数去填满它**。
3. **Boss 血量叠加方式脱离通用曲线。** 三个脚本 Boss 各自独立设定血量，倍率 1.91× → 4.02× → 8.94× 逐次放大，而玩家 DPS 在 W20 后只增长 21%（420 → 510）。W60 的压力 158.76 意味着 40 秒内只能清掉 0.6% 的投放血量。
4. **经验模型存在正反馈陷阱。** 击杀经验与「能否打过」绑定，导致落后方成长进一步减速；`sim` 口径（不补击杀经验）W60 DPS 仅 287，比 `real` 低 44%，说明经验来源构成对曲线非常敏感。
5. **曲线形状本身不平滑。** 首波缺口、W16–18 的意外回落、W42 后代际锯齿、Boss 波后断崖，共同造成体感上的「忽难忽易」，而非设计意图中的渐进爬升。

## 6. 模型边界与风险（读结论前必看）

| 项 | 说明 |
|---|---|
| **抽象结算，非实机战斗** | 供给 = `totalDps × 40s`，不含走位、弹道、射程、AOE 覆盖、控制链、单体溢出、怪物分批入场。实机清怪效率通常低于该模型 |
| **未计入的成长来源** | 圣遗物 / 红卡 / 天赋树 / 全局技能 / 三消技能 / 冰墙 / 广告复活 / 银币经济，均不在 `Run` 抽象模型内。这是**成长被低估**的主要方向 |
| **Boss 动态机制未计** | 迦尔文回血、薇拉 ward 护甲递增与周期召唤、罗塞娅召唤物，均未计入；Boss 强度是**下界** |
| **`skipLeak` 诊断模式** | 不扣城墙血，pressure 表示「40 秒内清不完的比例」，**不等于实机每波掉多少血**；实机 2000 血城墙会更早 game over |
| **护甲 0.85 截断** | 高护甲目标的真实减免可能被低估，进而低估有效血量 |
| **经验一阶滞后** | `real` 口径把上一波击杀经验在波末补发，因此 W1→W2 供给跳涨（3,255 → 5,795）是模型滞后，不是游戏内突变 |
| **难度固定** | 全部按 `DIFFICULTY.default = 6`（6 色）跑，未覆盖其它难度档 |
| **波次上限** | `WAVE.maxWave = 9999`，本文只算到 W60（三个脚本 Boss 覆盖完毕），更后期曲线未外推 |

**结论使用建议**：本模型适合回答「难度在哪一波开始发散、由哪条曲线脱钩造成」，不适合回答「应该把某个数值改成多少」。下一轮讨论调整方案前，建议先取实机埋点数据（每波实际击杀数、经验入账、DPS 贡献拆分、城墙掉血）校验本报告的成长曲线形状。
