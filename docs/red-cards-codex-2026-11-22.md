## 一、整理：现在 6 张圣庭红卡到底做了什么

### 1.1 通用规则（18 张卡全部共用）

| 项 | 规则 | 代码位置 |
|---|---|---|
| **槽位绑定** | **每张卡只能插在自己的 `nativeSlot`；一个槽只能放一张同塔卡 ⇒ 一塔一卡，不可换位** | `model.js:105-113`（待改） |
| 星级门槛 | 0★ 只有卡面；1★ 覆盖 4 格（2 绿 2 白）；2★ 覆盖 8 格（含 1 紫）；3★ 覆盖 12 格（含 1 紫 + 金） | `talents/model.js:41-49` |
| 白点 | 每格攻击 +2，**仅加成本卡所属塔**（卡永远在原生槽 ⇒ 恒生效，无失效态） | `model.js:88`、`damage.js:47`（flat 加法） |
| 绿点 | 每格给对应塔的百分比属性（时长/充能/技能/持续伤害等） | `model.js:87` |
| 紫点 | 需要 **2★ 以上**，且该卡的 `purpleNode` 坐标被**任一红卡覆盖**（不要求是同一张卡） | `model.js:67-69` |
| 金效果 | 3★ 自动激活，**每消除 12 个对应色块**攒一次机会，只保留 1 次储备 | `runtime.js:47-57` |
| 金消费 | 只在**普通命中**（非 dot、非技能）消费；炮塔例外，在开火时消费 | `runtime.js:93-96`、`attacks.js:53` |
| 色块→塔 | 红→fire 橙→cannon 紫→boomerang 黄→electric 蓝→ice 绿→poison | `runtime.js:7-14` |

两个容易被误会的点：

- **同塔永远只有一张卡**（槽位绑定）。所以「圣庭火 vs 熔铸火 vs 霜风火」是**三选一**的互斥关系，不存在同时充能、同时 ready、双金叠加。三套同塔卡吃同一个色块这件事只在「换卡」时产生影响，不产生叠加。
- **紫点覆盖仍然可以跨卡**。一张 3★ 卡覆盖 12 格，容易顺手覆盖邻卡的紫点坐标，所以「装 4–6 张 3★ 卡常年能激活 3–6 条紫」——这是星级带来的额外深度，与槽位绑定不冲突。

### 1.3 代码核对发现的 2 处偏差（需要处理）

| # | 现象 | 影响 | 处理建议 |
|---|---|---|---|
| S1 | 电金「雷脉传导」实际除了麻痹 0.5 秒，还会**挂 0.5 秒 / 50% 减速**（`runtime.js:116` 的 `applySlow(o,0.5,0.5)`），卡面没写 | 文案与实际不符；也是电紫「对麻痹 +15%」的隐式配套 | **已定：补文案、代码保留**。文案写「并附加短暂减速」，**不写具体秒数**——这段减速走公共入口，在霜风会被风压压到 0.33 秒，写死秒数会变成错的 |
| S2 | 紫点判定不排除技能命中（`beforeDamage` 的紫分支没有 `!skill` 判断） | 技能也能吃 +15%，强度略高于卡面描述 | 保留（属既有手感），但卡面别再写「普攻」二字，避免玩家抠字眼 |

> 原先记录的「炮金与命中消费抢 `ready`」已随**槽位绑定**作废：一塔一卡后不存在两张同塔金，`consume(tower)` 与 `attacks.js:53` 都保持原样，不需要改。

### 1.4 整理出来的核心问题：三套要同质化了

现有 6 张的紫**全是「对某种状态 +15%」**，金**全是「每 12 格一次」**。如果 12 张新卡照抄这个模板，18 张里有 12 张紫是同一个数值、同一个句式——玩家只会记「装 3★ 就变强」，记不住卡。

所以下面 12 张的设计原则是：**保留统一的充能节奏（每 12 格，不动核心），但每张卡的"作用对象"必须落在自己的战场机制上**，形成三条不同的因果链：

- 圣庭：元素两两联动（火↔毒、冰↔麻痹、炮↔回旋），互相铺垫；
- 熔铸：**削护甲 → 全队吃**，一条主链（熔穿）+ 一条续航（回能）+ 一条绕甲（硫毒）；
- 霜风：**挂风痕 → 减速 → 收束击杀**，一条主链（风痕）+ 一条硬控（冻结/麻痹）+ 一条扩散（连锁）。

## 二、熔铸系列（熔岩矿场 · `forge`）

> 定位：打不穿 + 弹药不够。-30% 弹药上限是底色，熔壳叠层是新压力（每 10 波 +1 层，普通护甲 +4%/层）。
> 六张卡里 4 张围绕「熔穿」转，玩家一眼能看懂因果。
> **工程口径见 `forge-six-cards-final-spec-2026-11-22.md`（2026-11-22 定稿）：数值、叠加、边界、验收断言以该文为准，本节只保留设计意图。**

### 2.1 熔铸·炽核熔炉（fire · 槽 0）

| 项 | 内容 |
|---|---|
| 紫（2★） | 火塔对**护甲 ≥15%** 的敌人，直接伤害 +15% |
| 金（3★） | 每消除 12 个红块，下一次火塔普攻**无视目标 50% 护甲**，并给目标挂「熔穿」3 秒（该目标护甲 −10%，不叠加，刷新计时） |
| 卡面文案 | 「削去半数护甲，并熔穿 3 秒——全队跟上。」 |
| 实现要点 | 无视护甲走 `damage.js` 的 `armorIgnore` 通道，不要改写 `e.armor`；「熔穿」= `e.armorBreak`（ttl 3），减伤处读 `e.armor - 0.10` |
| 视觉 | 命中处铁水裂纹 + 目标脚下暗红烙印 |

**为什么这张是全队的起点**：熔壳把护甲推到 54%（精英 68%），只有它能把护甲先撬开一个口子，其余 3 张「对熔穿 +15%」才有意义。

### 2.2 熔铸·膛压炉心（cannon · 槽 1）

| 项 | 内容 |
|---|---|
| 紫（2★） | 炮塔对处于「熔穿」的敌人 +15% |
| 金（3★） | 每消除 12 个橙块，下一次炮塔**击杀**返还 2 点能量；未击杀返还 1 点（均不超上限） |
| 卡面文案 | 「每一下都要换回子弹。」 |
| 实现要点 | 触发点是击杀回调，不是命中；与圣庭炮金（开火免能耗）是**两条独立通道**，可共存（见 R1） |
| 视觉 | 击杀时炮口回吸金色粒子，能量条 +2 跳出 |

**它是熔岩的续航**：弹药 −30% 的战场里，"击杀回能"是唯一能把输出节奏续上的东西，且必须搭配收割型塔（炮塔本来就是单体高爆发）。

### 2.3 熔铸·淬火槽（ice · 槽 4）

| 项 | 内容 |
|---|---|
| 紫（2★） | 冰塔攻击「熔穿」敌人 +15% |
| 金（3★） | 每消除 12 个蓝块，下一次冰塔普攻使目标「淬裂」3 秒：受到的所有伤害 +8%（同目标不叠加） |
| 卡面文案 | 「冷热交替，铁自己会裂。」 |
| 实现要点 | `e._quenchCrack` 在 `damage.js` 的最终减伤后乘 `1.08`；与熔穿（削护甲）是两种不同层，可叠 |
| 视觉 | 目标身上出现冰裂纹，命中时白蓝闪光 |

### 2.4 熔铸·硫磺脉（poison · 槽 5）

| 项 | 内容 |
|---|---|
| 紫（2★） | 毒 DOT 对**护甲 ≥15%** 的敌人 +20% |
| 金（3★） | 每消除 12 个绿块，下一次毒塔普攻附加 4 秒硫毒，累计 **45%** 攻击伤害，**无视护甲**，死亡不转移 |
| 卡面文案 | 「毒不走皮，走缝。」 |
| 实现要点 | 走 `_talentDots`，新增 `ignoreArmor:true` 与 `transfer:false`；秒伤 = 本次命中伤害 × 0.1125（4 秒累计 45%） |
| 视觉 | 黄绿黏稠毒泡，绕开护甲的"穿缝"轨迹 |

**它是打高血精英的第二解**：熔壳对毒也生效，但硫毒直接无视护甲，是唯一不被熔壳拖慢的持续输出。

### 2.5 熔铸·电弧熔渣（electric · 槽 3）

| 项 | 内容 |
|---|---|
| 紫（2★） | 电塔对「熔穿」敌人 +15% |
| 金（3★） | 每消除 12 个黄块，下一次电塔普攻额外**连锁 2 名 90 范围**敌人（各 60% 伤害）；命中「熔穿」目标时该次连锁 **+50%** |
| 卡面文案 | 「铁水通电，一路烧过去。」 |
| 实现要点 | 连锁目标取最近的 2 名（排除主目标）；`+50%` 只加成连锁部分，不加成主目标 |
| 视觉 | 熔渣电弧分叉，沿地面流痕扩散 |

### 2.6 熔铸·矿渣回旋（boomerang · 槽 2）

| 项 | 内容 |
|---|---|
| 紫（2★） | 回旋塔对「熔穿」敌人 +15% |
| 金（3★） | 每消除 12 个紫块，下一发回旋弹**返程**命中额外造成 **30% 攻击伤害**的碎渣伤害（穿透护甲，不返能量） |
| 卡面文案 | 「回来的不只是刀，还有渣。」 |
| 实现要点 | 挂在 `returnHit`（现圣庭回旋金同一入口），但只加伤害不给能量；穿透护甲 = 该段伤害跳过护甲计算 |
| 视觉 | 返程拖出暗红碎渣尾迹 |

## 三、霜风系列（霜风峡谷 · `gale`）

> 定位：数量多、跑得快。风压每 10 波 +1 层（移速 ×1.08ⁿ，满 5 层 ×1.47），并**压减速时长 −8%/层**（满 ×0.66，冻结不受影响）。
> 六张卡的分工：一张挂标记（回旋）→ 两张吃标记（电、炮）→ 一张硬控（冰）→ 一张收束（火）→ 一张持续（毒）。

### 3.1 霜风·凝霜之心（ice · 槽 4）

| 项 | 内容 |
|---|---|
| 紫（2★） | 冰塔对带「风痕」的敌人 +15% |
| 金（3★） | 每消除 12 个蓝块，下一次冰塔普攻使目标 **90 范围**敌人减速 35%（3 秒）；**若目标带「风痕」则改为冻结 0.6 秒**（冻结不吃风压抗控） |
| 卡面文案 | 「风里有痕，才有冰。」 |
| 实现要点 | 走 `applySlow` 与 `freezeE`；冻结分支必须绕过 `controlDurationPerStack` 乘区（战场效果的例外条款） |
| 视觉 | 冰晶沿风痕铺开，冻结时整片区域定格 |

**它是霜风唯一的硬停手段**：风压压减速，只有冻结能真正把怪钉住，所以这张卡在有风痕时价值陡增。

### 3.2 霜风·逆风回响（boomerang · 槽 2）

| 项 | 内容 |
|---|---|
| 紫（2★） | 回旋塔对**减速或冻结**中的敌人 +15% |
| 金（3★） | 每消除 12 个紫块，下一次回旋弹命中给目标挂「风痕」3 秒：移速 −25%，受到的**冰/电伤害 +8%** |
| 卡面文案 | 「顺着风回来，也把风带回来。」 |
| 实现要点 | `e._windMark`（ttl 3）；移速在 `main.js:565` 的乘区里再乘 0.75；易伤在 `damage.js` 按来源塔判定 |
| 视觉 | 回旋轨迹留下青蓝风线 |

**它是全系列的起手**：风痕是唯一能被 3 张卡吃到条件的标记，没有它整套霜风哑火。

### 3.3 霜风·静电风眼（electric · 槽 3）

| 项 | 内容 |
|---|---|
| 紫（2★） | 电塔对带「风痕」的敌人 +15% |
| 金（3★） | 每消除 12 个黄块，下一次电塔普攻额外**连锁 2 名 100 范围**敌人（各 50% 伤害，麻痹 0.4 秒） |
| 卡面文案 | 「风眼一转，电就散开。」 |
| 实现要点 | 与熔铸电金的区别：范围更大（100 vs 90）、单发更弱（50% vs 60%）、**给麻痹**（熔铸给 +50% 增伤） |
| 视觉 | 圆形风眼中心放电，向外分叉 |

### 3.4 霜风·霜蚀孢子（poison · 槽 5）

| 项 | 内容 |
|---|---|
| 紫（2★） | 毒 DOT 对**减速或冻结**中的敌人 +15% |
| 金（3★） | 每消除 12 个绿块，下一次毒塔普攻附加 4 秒霜毒（累计 **40%**）；**目标处于减速时延长 1 秒** |
| 卡面文案 | 「越慢，越吃毒。」 |
| 实现要点 | 走 `_talentDots`（`transfer:false`）；延长判定看 `e.slow.ttl > 0` 或 `e.frozen > 0` |
| 视觉 | 霜白色的孢子雾，黏在减速目标身上 |

### 3.5 霜风·融霜火线（fire · 槽 0）

| 项 | 内容 |
|---|---|
| 紫（2★） | 火塔对**冻结**中的敌人 +20%（全系列唯一 20%） |
| 金（3★） | 每消除 12 个红块，下一次火塔普攻对冻结目标造成 **2 倍伤害并解除冻结**，同时叠 1 层灼烧；解冻后目标获得 **1 秒「抗冻」**（期间无法被任何来源重新冻结） |
| 卡面文案 | 「冰一裂，火就进来。」 |
| 实现要点 | 解冻是**消耗行为**：结算完立刻 `e.frozen = 0` 并设 `e._thawImmune = 1.0`；免疫期内 `freezeE` 直接 return、`tickBaseStatus` 每帧把 `e.frozen` 压为 0（防同一帧被已排队的冰冻重新覆盖）；**免疫只挡冻结，不挡减速/麻痹**；1 秒写进常量 `THAW_IMMUNE`，便于调 |
| 视觉 | 冻结体炸成蒸汽，目标身上残留 1 秒灰白「防冻壳」描边（否则玩家会以为冰冻失效是 bug） |

**它是霜风的收束点**：冰控住 → 火打出 2 倍并解冻 → 怪重新开始走，但已经掉了一大截血。这套「控—爆—解」的循环是霜风区别于熔岩的手感。

### 3.6 霜风·霜炮轰鸣（cannon · 槽 1）

| 项 | 内容 |
|---|---|
| 紫（2★） | 炮塔对带「风痕」的敌人 +15% |
| 金（3★） | 每消除 12 个橙块，下一次炮塔爆炸使 **100 范围**敌人减速 30%（2 秒）；**命中「风痕」目标时半径 +30%** |
| 卡面文案 | 「一炮下去，风也慢了。」 |
| 实现要点 | 半径加成只影响范围，不影响减速值；与冰金的范围减速可叠（不同来源，`applySlow` 分别记 `_iceSlow` / `_genericSlow`） |
| 视觉 | 爆点外扩一圈风环 |

## 四、三套对比：怎么一眼分出是谁

| 维度 | 圣庭（ancient） | 熔铸（lava） | 霜风（frost） |
|---|---|---|---|
| 一句话 | 元素两两联动 | 撬开护甲，全队吃 | 挂上风痕，慢下来再打死 |
| 主链标记 | 灼烧 / 毒素 / 麻痹 / 回旋标记 | **熔穿**（护甲 −10%） | **风痕**（移速 −25%、冰电易伤） |
| 增伤结构 | 条件互喂（火吃毒、炮吃灼烧…） | 条件统一（4 张吃熔穿） | 条件分层（标记→减速→冻结） |
| 续航 | 回旋返 4 能量 | **炮塔击杀回能** | 无（靠控制换时间） |
| 收束手段 | 无（持续磨） | 硫毒无视护甲 | **冻结 + 火 2 倍解冻** |
| 卡面颜色 | 各自塔色描边 | `#e8603c` 赤橙 | `#5dade2` 青蓝 |

三套的紫都是 +15%（融霜火线 20%），但**条件不同、可叠方式不同**，玩家换战场时会换掉整条因果链，而不是只换数值——这是这次设计唯一要守住的底线。

## 六、槽位绑定带来的连锁影响（已按你的口径定死）

**已定：每张卡只能插自己的原生槽，一个槽只放一张卡 ⇒ 一塔一卡。**

这一条把原先待定的 3 个问题全部消掉，不用再选方案：

| 原问题 | 现在的结论 | 原因 |
|---|---|---|
| R1 同塔双金怎么消费 | **作废** | 同塔不可能有两张卡，`consume(tower)` 与 `attacks.js:53` 都不用改 |
| R3 熔穿被多张火卡反复刷新 | **作废** | 只有一张火卡能挂熔穿，刷新即自身刷新（3 秒） |
| 白点「只在默认槽生效」闸门 | **不需要** | 卡永远在默认槽，白点恒生效；不用做灰显、不用做 `lostAttack`、不用做卡面提示 |

因此削减了三块工作量：`model.js` 白点闸门、`talent-board.js` 白点灰显、`talent-actions.js` 的「换槽白点失效」提示。

**已拍板的两条（按此实现，不再讨论）：**

**R2｜融霜火线解冻后加「抗冻」，避免无限冰冻**
解冻瞬间设 `e._thawImmune = 1.0`（常量 `THAW_IMMUNE`）。三条约束：
1. 免疫期内 `freezeE` 直接返回；
2. `tickBaseStatus` 每帧把 `e.frozen` 压为 0（防止"同一帧已排队的冰弹"立刻把冻补回来，这是唯一会漏掉的地方）；
3. **只挡冻结**，减速、麻痹照常施加（否则控制流整体失效，霜风变成火塔无双）。

效果：同一目标最快 1 秒才可能再次被冻住，2 倍伤害最多 1 次/秒，不会出现"每发都 2 倍"的循环刷伤。表现上给 1 秒灰白「防冻壳」描边，让玩家知道是规则而不是 bug。

**R4｜电金隐藏减速：补文案、代码保留**
`runtime.js:116` 的 `applySlow(o,0.5,0.5)` 保留，卡面补「并附加短暂减速」。**文案不写具体秒数**：这段走 `applySlow` 公共入口，在霜风会被风压压到约 0.33 秒，写死「0.5 秒」会变成错的。

**附带一条从审阅补充里继承的规则（R5）**：需要条件的金效果（霜风火=需冻结、熔铸淬火等）在条件不满足时**不消耗 `ready`**，保留给下一次符合条件的机会；不符条件时不得"顺手消费"。

**顺带提醒一个后果**：一塔一卡 ⇒ 熔铸火与圣庭火是互斥选择。老玩家已经练满圣庭火，凭什么去练熔铸火？靠**熔岩的熔壳只被熔铸卡反制**（熔穿 −10% 护甲、硫毒无视护甲），圣庭火在熔岩打不出反制环——不靠数值拉，靠战场规则拉。熔壳别被削到可有可无，它是两套新卡"被用起来"的前提。
