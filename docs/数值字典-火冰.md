## 0 读前必读：三个单位约定

| # | 约定 | 为什么容易错 |
|---|---|---|
| 1 | **伤害系数乘的是「单发普攻伤害」**（`shotDmg()` 的返回值），不是面板 DPS | 火塔 `atkInterval=0.9s`、冰塔 `1.1s`，`shotDmg = 面板DPS × 间隔`。把 0.44 当成「面板 DPS 的 44%」会算错约 10%~40% |
| 2 | **半径/宽度/偏移 = 逻辑像素**（750×1626 设计稿） | 真机 375pt 宽时为显示值的一半 |
| 3 | **时间是秒**；**概率/百分比是 0~1 小数** | 配置里 `0.30` 意为 30%，不是 30 |
| 4 | **分支档位数组 `[0, x1, x2, x3]`**，下标 = 该分支等级（0 = 未点），档位之间**不累加**，取当前等级那一个值 | 写 `(1 + arr[lv])` 的字段是「加算百分比」；写 `arr[lv]` 的是「绝对值」——两种都有，见每张表的「用法」列 |

## 1 乘区总图（两段式）

伤害进 `damage()` 之前只经过两条路，**先算技能系数，再乘塔的全局乘区**，顺序是固定的：

```
① 面板 DPS（三消等级成长 × 塔基础 32/20 …）
   × atkInterval                      ← 折成「单发伤害」= shotDmg 的输出
② shotDmg(key, isSkill) 内 7 个乘区（combat.js:187，顺序即代码顺序）
   1 × 全局锻造           gsState.forge > 0 → ×1.25          （config/global-balance.js）
   2 × 局内商店攻击强化   (1 + 0.2 × 层数)                   ← 本局临时
   3 × 圣遗物伤害%        (1 + rl/100)  rl = 力量符 + 塔遗物 + 4连叠层 + 城墙背水
   4 × 全局充能3★技能伤   (1 + chargeSkillBoost/100)  ← **仅 isSkill=true 时生效**
   5 × 洗牌增益           _shuffleBuffTtl > 0 → ×1.3
   6 × 能量耗尽弱化       能量 ≤ 0 → ×0.5                     （CONFIG.GLOBAL_SKILL.weakDmg）
   7 × 周期弱化           period × 1.5（只影响周期技释放间隔，不改伤害）
③ 技能基础系数            本文各表的「基础值」列
④ 分支倍率                本文各表的「档位」列，每技能只乘其中一个分支的档位
⑤ 爆炸附加乘区            explode() 内：协同[1]（重炮×大火球）达成 → ×1.5  ← 见 §2-P3
```

**自检口诀**：一个技能的最终伤害 = `shotDmg × 技能系数 × (1 + 分支档位)`。表里只要出现第四个乘法项，就是特例，会在「说明」列标出来。

## 2 乘区检查结论

> 本节只陈述事实与证据，**不判定是否为 bug**；是否修、怎么修由 Codex 在迁移时决定（任务单：W 不直接修改 combat 或默认参数）。

### P1 火柱有两个「看着能调、实际调不动」的字段 🔴

| 字段 | 配置值 | 实际生效值 | 证据 |
|---|---|---|---|
| `fire.火柱.emberDuration` | 3 (s) | **硬编码 3** | C2040 `ttl: 3` 字面量 |
| `fire.火柱.emberDamagePerBranch` | 0.15 | **硬编码 0.15** | C2040 `* 0.15 * wv.ember` |

**影响**：策划改这两个值不会有任何效果，且配置与实机表现静默不一致（最难查的一类问题）。
**复现步骤**：
1. 把 `emberDuration` 改成 10、`emberDamagePerBranch` 改成 1.0
2. 学火柱 + C 余烬分支，在空地放火柱
3. 观察地面余烬：仍为 3 秒、伤害仍为 15%/级
**建议判定口径**：迁移时一并改为读配置（余烬 DPS 公式 = `shotDmg(true) × emberDamagePerBranch × emberLv`，地面 DoT 时长 = `emberDuration`）。

### P2 `isSkill` 标记口径不一致（决定「全局充能3★技能伤」吃不吃）🟡

| 技能 / 路径 | 代码 | isSkill | 是否吃技能伤 |
|---|---|---|---|
| 火柱 | C2015 | ✅ true | 吃 |
| 烈焰墙 撞击 | C2068 | ✅ true | 吃 |
| 烈焰墙 持续灼烧 | C2097 | ✅ true | 吃（作为灼烧来源伤害） |
| 火雨 每波 | C2129 | ✅ true | 吃 |
| 火雨 天火一击3★ | C2171 | ✅ true | 吃 |
| 爆燃 击杀爆炸 | C1034 | ✅ true | 吃 |

| **冬珠** | C2483 | ❌ 未传 | **不吃** |
| **碎冰 B** | C2333 | ❌ 未传 | **不吃** |
| **冰穿刺 C 冰霜透射** | C2397 | ❌ 未传 | **不吃** |

**为什么值得提**：冰花（8s 周期）、冬珠（10s 周期）与火柱（10s 周期）是同一类「周期技」，火柱吃技能伤、冰花/冬珠不吃；同一件圣遗物对同类技能的效果不一致，玩家侧表现为「充能3★只强化火系周期技」。
**复现步骤**：
1. 存档给 `chargeSkillBoost = 100`（或带满级全局充能3★）
2. 同面板下分别施放火柱与冰花，记录单次伤害
3. 火柱伤害约为无加成时的 2 倍，冰花不变
**连带影响**：`碎冰` 与 `冰冻 C 碎冰` 名字相近但口径不同（一个吃、一个不吃），调参时极易误判。

### P3 `explode()` 的 1.5 协同加成不判塔别 🟡

C1034 附近的 `explode()` 内部：`if (synergyDone[1]) mult *= 1.5`，**不判断 `key`**。
协同[1] 名为「重炮×大火球」，但只要达成，火系所有走 `explode()` 的伤害一并 +50%：

| 受影响路径 | 代码 |
|---|---|
| 火柱爆发 | C2036 `explode(wv.r …)` |
| 火雨 燃尽加速3★ 附爆 | C2183 |
| 爆燃 击杀爆炸 | C1034 |
| 灼烧 B 燃尽 满层爆 | C1991 |
| 冰冻 C 碎冰 / 冰穿刺 | C1112（冰系也吃） |

**复现步骤**：达成重炮×大火球协同后，只放火柱（不放炮塔攻击），对比协同前后火柱单次伤害 → +50%。

### S1 快照语义：周期技伤害在「施放瞬间」定值 🟢（非问题，但影响测试判断）

| 技能 | 快照字段 | 代码 |
|---|---|---|
| 火柱 | `pillarWaves[].dmg` 施放时算好，0.6s 后结算 | C2015→C2036 |
| 火雨 | `rainWaves[].dmg` 每波按施放时面板算 | C2129→C2179 |
| 冬珠 | `frostOrbs[].dmg` 每跳沿用施放时的值 | C2483→C2499 |
| 冰墙 | `absorb` 施放时 300，后续不再随面板变化 | C2556 |

**含义**：施放后 1 秒内吃到的攻击强化 / 圣遗物加成**不会**追补到已生成的波次与冰珠上。测试「改参是否生效」时必须在**施放前**改，施放后改看不到变化。

### S2 不走 `shotDmg` 的伤害（不在塔乘区里）🟢

| 伤害 | 公式 | 代码 |
|---|---|---|
| 冰墙 B 霜反 | `吸收量 × reflect` | C2557 |
| 冰墙 C 融暖回血 | 直接加 `lineHp`，上限 `lineMaxHp` | C2533 |
| 灼烧 DoT | `来源伤害 × damagePerSecond × (1+余烬) × (1+薪柴)` 后按 tick 结算，**不再乘 shotDmg** | C1966 |

**含义**：给塔加攻击强化时，反伤与回血不跟着涨（它们不是「伤害系数×攻击力」结构），预期如此。
