# R08 存档边界与深层隔离（2026-10-30）

## 文件与职责

- js/save/snapshot.js：复制存档数据的数组和嵌套对象，不对Meta/Run运行实例做序列化复制。
- js/save/migrations.js：原v1/v2升级与冰/电技能改名迁移函数。SaveManager保留旧方法名兼容委托。
- Meta.fromJSON：先取得独立快照，再按旧字段和默认值恢复。旧relicSlots补持有数不修改原输入。
- Meta.toJSON：只返回存档字段的独立快照；档案后续变化不改写已导出对象，修改导出对象也不改变活档案。
- SaveManager.load：存储返回值也先复制，迁移不修改存储对象；保留正常/测试存档键。
- account.switchProfile：保存原档失败、读取目标失败、首次写入目标失败时停止切换并保留原档案；不清理用户数据。

## 字段所有权

| 类型 | 字段 | 所有者与规则 |
|---|---|---|
| 格式 | version | 固定v5，旧版本按原规则迁移 |
| 标量 | gold、diamond、chests、starStones、bestWave、totalDiamondSpent、musicOn、soundOn | 当前Meta；复制值 |
| 旧圣物 | relics、relicLevels | 当前Meta的独立对象，保留旧养成兼容 |
| 图鉴/成长 | runCodex、towerCodex、relicStars、shards | 当前Meta独占；不指向定义表或输入快照 |
| 宝箱 | chestTimer、deepChests及各箱对象 | 当前Meta独占；深拷贝列表内的每个箱体 |
| 每日数据 | dailyPicks及picks商品、shopDaily及chests计数、dailyFirst及counts | 当前Meta独占；不与其他档案共享 |
| 技能 | matchSkills、globalSkills及slots、skillUnlocks及各槽数组 | 当前Meta独占；保留全局双槽归一化规则 |
| 进度 | milestones | 当前Meta独占 |
| 历史塔位 | towerUnlocks | 导出快照独立；恢复仍按既有规则清空，出战塔每局先消先得 |

配置定义/函数/renderer/combat/Run引用不写入档案。未新增云端账号或跨设备同步。

## 异常和异步保护（明确行为修复）

读取状态：missing / ok / unsupported / error / unavailable。未知版本、非空损坏根数据或读取异常返回null但同时阻止对该存档键的自动写入，避免fallback空档覆盖原数据。正常缺档仍可创建；成功重读解除保护；明确调用clear后允许新档保存。本批不自动清档。

save()明确返回true/false，原调用方可继续忽略；切档入口使用返回值决定是否继续。口令回调校验请求序号、存档键和原页面引用；页面或档案切换后旧回调无效。

不宣称完成全部损坏字段的schema校验：支持版本中嵌套字段类型的完整归一化、未来版本迁移、跨进程写冲突仍需独立设计。此处只修复引用共享与明确的读写失败保护，不静默重算玩家资产。
