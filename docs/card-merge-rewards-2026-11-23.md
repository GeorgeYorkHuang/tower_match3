# 抽卡充能 · 合成 2★ / 3★ 奖励设计（v1，2026-11-23）

> 状态：设计稿（未实施）。范围只覆盖「新抽卡机制下 3 张同卡合成」的奖励，不含红卡圣物升星、不含三消残留清理。
> 基线：v1.19.7 / `00859a2`。所有代码事实均按 2026-11-23 0:43 之后的 `js/tower-cards.js`、`js/game/screens/card-draft.js` 实读。

---

## 0 一句话结论

现在的合成是「自动 + 静默 + 能量收益被上限截断」的三重无感：3★ 的 +80 能量必然溢出、合成没有任何提示、建满 4 塔后抽到的另外 2 塔全是废卡。建议把合成奖励拆成三层——**①卡内能量（维持现状）②「合成账簿」本局永久伤害成长（永不溢出）③满能量溢出出口 + 建满塔收窄卡池**，让「攒卡合成」变成一条可见的成长轴，而不是一个看不见的 33% 能量折扣。

## 1 代码现状（先锚定事实）

### 1.1 机制链

| 环节 | 实现 | 关键数值 |
|---|---|---|
| 抽卡 | `tower-cards.draw(run)` | 一次抽 **3 张 1★**；`draws >= 3` 后每次 **100 银币**，前 3 次免费 |
| 池 | `Object.keys(CONFIG.TOWERS)` 均匀随机 | **6 塔全量**，与战场/难度无关 |
| 合成 | `merge(cards)`，`draw()` 抽完立即调用 | 同 `key` 同 `star` 满 3 张 → 1 张 `star+1`，循环到稳定；**3★ 不再合** |
| 卡槽 | `state.cardDraft.unlocked`，初始 8、上限 10 | 红卡 3 张 +1、6 张 +1，其余看广告 |
| 使用 | `use(run, index, slot)` | 空槽 → 建塔；同类塔 → 充能；**塔已满 → 直接 `return {ok:false, reason:'能量已满'}`** |
| 建塔初始能量 | `energy = min(cap, 20 + charge)` | 1★ 建塔 = 25、2★ = 40、3★ = 100（直接满） |

### 1.2 能量换算（这决定了奖励必须绕开能量）

`RULES.energy = [0, 5, 20, 80]`，配合 `GLOBAL_SKILL.energyMax = 100`、`perAttack = 0.5`：

| 卡星 | 能量 | 折合普攻次数 | 相对 cap（100） |
|---|---|---|---|
| 1★ | +5 | 10 发 | 5% |
| 2★ | +20 | 40 发 | 20% |
| 3★ | +80 | 160 发 | **80%，单卡必定把塔推到满** |

塔能量上限 = `100（基础）+ 军火库 30 + 弹药库圣遗物 10/20/30 + 颜色 +N`，再 `× fieldAmmoMult`、再 `− 电磁过载扣减`。绝大多数塔的 cap 落在 100~140。

### 1.3 合成在数学上只赚 33% 能量，且 3★ 那一档会被截断

- 3×1★（合起来 15 能量）→ 1×2★（20 能量）：净赚 +5，即 **+33%**
- 3×2★（合起来 60 能量）→ 1×3★（80 能量）：账面 +33%，但**塔的实际吸收上限就是 cap-当前能量**，两张 3★ 卡先后拖上去收益几乎为 0

## 2 四个设计缺口（为什么必须设「奖励」）

| 编号 | 缺口 | 代码证据 | 玩家感知 |
|---|---|---|---|
| A | **3★ 档能量收益被 cap 截断** | `use` 里 `tower.energy=Math.min(cap, …)`；cap≈100，单卡 +80 | 「合到 3★ 感觉跟 2★ 一样」 |
| B | **合成全自动且零反馈** | `merge()` 只改 `cards` 数组，无 toast、无动画、无弹窗；`card-draft.js render` 只画塔名/★/+N | 「三张卡忽然变成一张，不知道为什么」 |
| C | **建满 4 塔后 33% 的卡是废卡** | 池 = 6 塔，`TOWER_SLOTS = 4`，`use` 里非本塔一律 `请拖到同类塔充能` | 后期每 3 张卡就有 1 张永远拖不动 |
| D | **满能量塔吃不了卡** | `if(tower.energy>=cap) return {ok:false, reason:'能量已满'}` | 中后期塔常年满能量，卡在卡槽里堆死、抽卡按钮跟着报「卡槽不足」 |

> 缺口 D 会连锁触发缺口 B 的后果：卡槽 8 个位置一旦被满能量塔的卡占满，`draw()` 直接返回「卡槽不足，请先使用塔卡」，而玩家又用不掉——抽卡循环彻底堵死。

---

## 3 设计原则

1. **奖励不能只挂在能量上**——凡是以能量计的收益，都会被 cap 吃掉。必须有一条不经过能量的收益通道。
2. **结算点只有两个**：`merge()`（合成瞬间）和 `use()`（使用瞬间）。不新增第三个交互环节。
3. **不改抽卡价格**（100 银币 / 前 3 次免费），不改卡槽 8/10，不改 `RULES.energy` 现值。
4. **不新增货币、不新增养成表**——账簿存在 `run` 上，随本局结束消失。
5. **合成保持自动**（不引入「手动拒绝合成」的交互），因此账簿是对「被剥夺的分散充能选择权」的补偿。

## 4 主案：三层奖励

### 4.1 2★ 合成（3×1★ → 1×2★）

| 项 | 内容 |
|---|---|
| 能量 | **+20**（现值不动，40 发普攻） |
| 账簿 | 该塔 **伤害 +3%**（本局永久，加算） |
| 满能量时 | 20 点转「全局技能充能」，洗牌/补给各 +10（见 4.4） |
| 反馈 | 卡面显示 `★★ · +20⚡ · +3%`；合成瞬间 toast：「合成 火焰★★ · 伤害 +3%」 |

### 4.2 3★ 合成（3×2★ → 1×3★）

| 项 | 内容 |
|---|---|
| 能量 | **+80**（现值不动，通常一次推满） |
| 账簿 | 该塔 **伤害 +8%**（本局永久，加算） |
| 合成瞬间 | 额外给 **全局充能 +10**（洗牌 +5 / 补给 +5）——这是 3★ 唯一的「即时爽点」，绕开塔能量所以不会溢出 |
| 满能量时 | 同上，80 点按 1:1 转全局充能 |
| 反馈 | 卡面 `★★★ · +80⚡ · +8%`；金色 toast：「合成 火焰★★★ · 伤害 +8% · 全局充能 +10」 |

### 4.3 账簿规则（关键）

| 规则 | 定值 | 理由 |
|---|---|---|
| 存储 | `run.cardGrowth[key]`（百分点，浮点累加） | 跟 `run` 走，局末自然消失，不进存档 |
| 单塔上限 | **+20%** | 2★ 5 层（+15%）+ 3★ 2 层（+16%）已能触顶；20% ≈ 一个强圣遗物词条，不破坏平衡 |
| 触顶后 | 不再累加伤害，**能量与全局充能照给** | 避免「合成变成负收益」 |
| 乘区位置 | 并入 `damage.js:48` 的 `rl`（与力量符 `cm_power`、塔圣遗物伤害同区加算） | **普攻与全部技能同吃**，口径与现有力量符完全一致，不新增乘区层 |
| 未建塔 | 正常记账，建塔后立即生效 | 抽卡常早于建塔，不能因此丢弃奖励 |
| 显示 | 卡面不再显示，改在**塔信息面板**显示「合成 +N%」 | 卡被用掉就消失，账簿必须在塔上可见 |

### 4.4 溢出出口（补缺口 D）

`use()` 的拒绝条件改成：

```
可充能能量 = charge
实际吸收 = min(charge, cap - tower.energy)
溢出 = charge - 实际吸收
若 溢出 > 0 → 溢出按 1:1 转为全局技能充能（洗牌/补给各一半，受 energyMaxGS=90 封顶）
若 全局充能也已满 → 才允许 return {ok:false, reason:'能量与充能均已满'}
```

配套要求：**塔满能量不再阻止用卡**，这一条必须改，否则缺口 D 的「卡槽堵死」无法解决。

### 4.5 卡池收窄（补缺口 C）

`draw()` 的取 key 逻辑加一层过滤：

```
若 run.slotOrder.length >= run.towerSlots（4 座塔已建满）
→ 只从 run.slotOrder（已建 4 塔）中抽
否则 → 维持 6 塔全量
```

效果：建满塔之前保留「挑塔」的自由度，建满之后抽卡 100% 有效，废卡率从 33% 降到 0。这是本方案里唯一影响掉落期望的改动，但它只提高**有效性**、不提高**总能量**（银币成本不变）。

## 5 数值验算

### 5.1 出卡期望（池 6 塔均匀）

| 目标 | 需要张数 | 期望抽卡次数（每次 3 张） | 期望银币（前 3 次免费后计） |
|---|---|---|---|
| 1 张 2★ | 同塔 3 张 | 6 次 | 约 300 |
| 1 张 3★ | 同塔 9 张 | 18 次 | 约 1500 |

### 5.2 账簿实际强度

按一局 12 次抽卡（36 张）估算：单塔约 6 张 → 2 层 2★ + 偶尔 1 层 3★ → **单塔 +6%~+14%**，主战塔吃满、副塔吃一半。极端满抽 18 次也只到 +20% 上限。

对照现有乘区：圣庭紫卡对特定状态目标 +15%、力量符按星级 +N%、熔铸淬裂 +8%——**账簿的量级与一个紫卡效果相当**，属于「可见但不主导」的档位。

### 5.3 平衡风险

- 账簿并入 `rl` 是**加算**，与红卡紫/金、力量符同区 → 后期大乘区叠加时会略微抬高高投入玩家的上限，但 +20% 封顶可控。
- 全局充能溢出出口会让「满能量塔」的卡变成「全局技能次数」，等于变相提高洗牌/补给的使用频率；`energyMaxGS = 90` 已是硬顶，不会无限。
- 卡池收窄只影响有效性，不影响单卡能量值。

## 6 已否决的备选（记录理由，防反复）

| 备选 | 否决理由 |
|---|---|
| 合成返银币（2★ 返 30 / 3★ 返 100） | 直接改经济循环，等于给抽卡打折；且返多少都会诱发「为返现而抽」的次优策略 |
| 合成送免费抽 | 同上，且与「前 3 次免费」的引导节奏冲突 |
| 合成时给塔「攻速爆发」3~5 秒 | 强依赖「塔已建」这一前提，抽卡早于建塔时奖励直接作废；且与现有攻速乘区难验收 |
| 允许手动拒绝合成 | 需要新增拖拽/长按交互，成本高于收益；账簿已经是更好的补偿方案 |
| 只提高 `RULES.energy`（如 3★ 改 +120） | 加剧缺口 A——cap 只有 100，+120 是纯浪费 |

**验收条件（逐条可验）**

1. 合成 3×1★ 后，`run.cardGrowth[key]` 精确 +0.03，伤害数字同比提升，累计不超过 0.20。
2. 合成 3×2★ 后，`run.cardGrowth[key]` +0.08 且洗牌/补给各 +5 充能。
3. 塔满能量时拖 3★ 卡成功，溢出部分进入全局充能，`energyMaxGS` 到达 90 后卡不能再被消耗并给出正确 reason。
4. 4 塔建满后连抽 100 次，出现非 `slotOrder` 塔的概率为 0。
5. 手动抽卡与自动抽卡（`storeTimers.auto`）两条路径都能弹合成提示。
6. 触顶 +20% 后继续合成，伤害不再增长但能量/充能照给。

## 8 待确认（需要拍板后才能进入施工）

1. **账簿上限 +20% 是否可接受**——若担心后期乘区通胀，可降到 +12%。
2. **3★ 合成瞬间的 +10 全局充能**是否保留（不放宽的话 3★ 相对 2★ 只多 +8% 账簿，爽点偏薄）。
3. **卡池收窄的边界**：建满 4 塔就收窄，还是「建满 4 塔且首 4 塔已定型」？另外「未解锁的第 5/6 塔」在未满 4 塔时抽到，是保留还是也过滤？
4. **塔未建时合成的账簿**是否需要在 UI 上预先提示（「该塔尚未建造，奖励将在建塔后生效」），否则玩家会以为奖励丢了。
