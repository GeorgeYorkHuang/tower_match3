# R14第一批：圣遗物击杀触发

## 边界与接入

`js/relics/kill-hooks.js`不保存Combat、Game、Run或Enemy引用，每次显式传入。它调用现有Combat伤害/状态/特效接口，不复制伤害公式。共享配置仍由config/tower-skills与config读取。

| 导出 | 原位置/调用时机 |
|---|---|
| fireDeath | Combat.onKill，火塔且目标有灼烧时；火种与余烬风暴 |
| fireExplosionSpread | 爆燃技能成功爆炸后；连锁爆破传染 |
| poisonInheritanceBase | 毒爆传染随机成功后、B继承随机判定前；瘟疫之源基础层数 |
| poisonEssence | 毒爆之后、毒藤之前；毒满层死亡溅射 |
| poisonTrail | 毒藤C已找到并缠绕下一目标后；蔓延毒痕 |
| iceDeath | 冰冻C技能碎冰之后；霜爆与霜刺扩散 |
| electricDeath | 冰塔效果之后；静电麻痹扩散 |
| hunterTransfer | 猎手标记C原有扩散之后；猎心满层标记转移 |
| boomerangDeath | 标记技能之后；血刃扩散与追猎返还能量 |
| cannonDeath | 六塔轮询末尾；燃烧弹死亡爆炸 |
| experience | Main.onKillReward，测试战场早退后；含局外经验加成与经验之心 |
| eliteChestChance | Main精英分支；含寻宝罗盘与赏金猎人概率乘区 |

这些函数分点接入，不能合并到统一“死亡末尾”调用：爆炸可递归导致另一怪物死亡，随机次数、状态读取与先后顺序都影响结果。基础技能的爆燃/毒爆/碎冰/标记仍在Combat；基础击杀银币、金币增益技能倍率、碎片暂存、Boss宝箱和存档仍在Main。精英宝箱随机判定与bountyGuarantee短路顺序不变。

## 验证

`tools/_test_kill_relic_hooks.cjs`以固定1b0274f旧函数为基线：

- 986组死亡触发组合：13个单独圣遗物各1/2/3档、全部关闭/全部开启、技能未学/分支3档、目标有无状态、塔顺序正反、三组固定随机种子及两组爆炸递归死亡。
- 384组奖励组合：普通/精英/Boss/未知类型、Boss标记、战场/测试场、掉落关闭、经验/宝箱加成与保底；逐次对比RNG次数、调用顺序、经验、宝箱、碎片、银币和特效状态。
- 状态隔离：对一个Combat触发不修改另一个Combat。
- 既有多弹道、彩虹消耗/充能、消除圣遗物72组、战斗路由56组、真实Main商店15项、wx触摸18项及存档隔离回归通过。

输入组合是自动验证，不代表1370次手动或真机测试。未调整P2/P3或任何数值。此前P2/P3按combat行号登记的调用点部分迁到kill-hooks，后续静态扫描须同时覆盖这两个文件，不能用combat单文件调用数判断缺失。
