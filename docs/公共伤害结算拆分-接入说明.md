# R15第三批：公共伤害结算拆分

## 接口与所有权

`js/combat/damage.js`导出三个显式接收Combat的函数，原Combat方法保留签名和返回值，调用点不改：

- `shotDmg(combat, key, isSkill)`：攻击基数和出手时伤害乘区，继续读取当前Run、塔能量、配置与圣遗物，不缓存结果。
- `damage(combat, enemy, amount, sourceKey)`：目标减伤/易伤等乘区、扣血与伤害来源记录、死亡防重入标记、击杀计数及onKill。
- `explode(combat, x, y, radius, amount, key, knock, slowAfter, exclude)`：范围枚举、原协同倍率、排除主目标、伤害/击退/减速/点燃、军火之王叠层与表现。

所有可变数据归当前Combat、Run或Enemy。模块仅持有共享配置；不保存玩家、敌人、定时器或全局击杀账本，不向Config写入。目标查找、状态施加、伤害回调与表现继续经Combat方法调用，伤害公式只有此一份。

## 保持原顺序和行为

shotDmg保留DPS×基础攻击间隔、锻造、商店强化、圣遗物加成、isSkill技能伤、洗牌窗口和能量耗尽弱化。乘法顺序不变。

damage继续先跳过已死目标，再按原顺序算护甲/易伤/圣遗物，扣hp并记录lastDmgKey。首次死亡时先置_dying、按本次来源增加kills，再调用onKill。onKill爆炸可能同步造成另一死亡，不能延后或批量处理。

explode继续逐目标结算后再施加击退/减速/点燃，最后叠军火之王与推送特效。保留原有：协同[1]对各塔爆炸均生效、能量弱化、不同来源isSkill漏传/保留口径等历史行为；本轮不实施P2/P3，不顺手修正文案与实现差异。

护盾指城墙保护时，仍属于Run.applyWallDamage，不在敌人伤害模块内；本批未移动城墙结算、掉落记账或波次流程。状态工具、DoT计时、技能施放仍留Combat，待下一批按依赖提取。

## 验证

`tools/_test_combat_damage.cjs`固定读取3b7e09b旧Combat源码：

- 108组出手伤害：六塔、普攻/技能标记、加成开关与能量状态。
- 504组扣血：六塔/无来源、叠加状态、护甲0/50%/85%/100%、目标已死/濒死/高血、零/小数/致死伤害及重复命中。
- 78组单独乘区：灼烧真火、标记、过载、塔圣遗物与局外加成等，避免只测全叠加而掩盖某个遗漏。
- 192组爆炸：六塔、协同与圣遗物开关、击退、减速、排除目标、不同随机种子；比较目标状态、计数、特效、回调与随机调用次数。
- 额外断言：递归死亡先置标记/计数、同尸体不重复结算、护甲85%封顶、充能仅提升isSkill伤害和双Combat独立。

回归通过：目标648组、弹道456组、多重火球/冰锥与延迟发射、焰雨3★、击杀1370组、波次554组、撤离检查点11项。

没有改页面；本批未重跑旧技能界面的触摸测试，其连消弹窗用例仍需随新规格更新。没有合入并行美术资源或skill-loadout改动。新模块不由Renderer加载，无需增加HTML绘制预览内联。

## 后续静态扫描定位

P2/P3及数值字典需按符号定位；damage/explode主体已从combat.js迁到combat/damage.js，死亡圣遗物调用在relics/kill-hooks.js。未来统计调用点须区分兼容委托与业务调用，不能只扫combat.js行号或把委托重复计数。

## 用户设备抽查

1. 同一塔能量充足/耗尽时伤害变化保持原样，商店攻击强化有效。
2. 爆炸连续击杀不重复增加击杀数/奖励，普通/精英/Boss仍能正常被击杀。
3. 炮弹范围伤害、击退与减速正常，多弹道命中不受影响。
