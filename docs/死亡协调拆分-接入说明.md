# 公共死亡协调拆分接入说明

R15第十七批，固定基线cddaffc。

## 边界与所有权

新增js/combat/death.js，导出onKill(combat,e)，原Combat.onKill(e)保持同名委托。模块只读tower-skills，复用relics/kill-hooks；不持有模块级战斗状态，不反向依赖Combat。所有临时变量留在调用栈，敌人状态/区域/能量仍归原实例。

死亡协调按run.slotOrder.slice()快照逐塔执行，保留火系圣遗物与爆燃、毒爆传播/毒藤延伸、冰冻碎冰、电系圣遗物、猎手标记传播与炮系挂点的交错顺序。爆炸可以同步进入另一个敌人的onKill，内部死亡完整处理后再返回外层；死亡表现、音效及onKillReward仍在各次死亡末尾。

伤害模块仍负责hp与_dying门禁、击杀计数以及数字事件先于死亡回调，death模块不新增二次门禁，也不改变直接调用onKill的历史语义。经验、掉落与资产入账仍由game层及原奖励模块负责，本批不修宝箱碎片、不实施P2/P3。

## 验证

node tools/_test_combat_death.cjs从git show cddaffc:js/combat.js提取旧onKill，3938组对比覆盖圣遗物独立星级与组合、技能0—3档、状态开关、正反出战顺序/空队伍/重复项及固定随机种子，记录传播目标、状态、能量、区域、表现、奖励与随机数消耗。同步递归和运行中修改出战列表另有快照对比。

另接入真实damage/explode，用6敌连续爆炸验证每敌计杀/奖励一次、重复伤害不再奖励、实际伤害数字先于对应奖励，及实例隔离。大组合测试对伤害/状态使用记录桩；实际公式与传播模块由已有回归补充。击杀/奖励1370组、伤害882、状态432、区域1296、回旋镖攻击2304及真实Main反馈/Run连消通过。
