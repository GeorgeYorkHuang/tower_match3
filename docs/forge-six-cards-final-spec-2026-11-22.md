## 1 六张共用约定（先落这 5 条，否则单卡验收不成立）

### 1.1 伤害链与插入点（`js/combat/damage.js`）

现有顺序（已核对）：`shotDmg` → `beforeDamage`（天赋，`:90`）→ `armorIgnore`（`:92`）→ 护甲（`:93`）→ 腐蚀 → 真火 → 其它乘区。

熔铸需要的插入：

| 步骤 | 内容 | 位置 |
|---|---|---|
| ① | 本次命中的"无视护甲 %"（炽核熔穿 50%）并入 `armorIgnore` | `:92`，`Math.max` 合并 |
| ② | 护甲公式改为 `armor_eff = max(0, e.armor − armorBreak) * (1 − armorIgnore)`，再夹 `0.85` | `:93`（**结构改动，见 5.3**） |
| ③ | 淬裂 +8%、风痕冰电 +8% **加算合并**成一次乘法 `1 + 0.08 + 0.08` | `:96` 之后（真火之后） |
| ④ | dot 的"跳过护甲"标记，命中 `:93` 时直接不乘 | `:93` |

顺序结论（给工程的一句话）：**易伤加算、护甲乘算、无视护甲按百分比先削、熔穿按绝对百分点后减**。乘法交换，谁先谁后只影响可读性，但 ③ 必须合并成一次（否则 1.08×1.08 与 1.16 差 0.5%，测不准）。

### 1.2 紫点条件口径（火紫 ≥30%、回旋紫 ≥15%）

「有效护甲 ≥30% / ≥15%」一律读 **`e.armor`（含熔壳加成、不含熔穿减益）**。

理由：熔壳是加护甲，条件应该更容易满足；熔穿是玩家自己造成的减益，如果它反过来让紫条件失效，会出现"越打越弱"的怪现象。

> **紫名额与档位分布**：熔铸 **2 个紫生效**（按 `nativeSlot` 升序取前 2），6 张全有紫（4 双 + 2 只紫 + 0 只金），所以紫条件是 2/6 的竞争。档位分布、中间紫卡槽（电卡紫点改到盘心 `0,1`）与形状改法见 `purple-slots-and-series-tiers-2026-11-22.md` 第 2、3 节。

### 1.3 `ready` 消费三类（六张卡分别落在其中一类）

| 类型 | 规则 | 适用 |
|---|---|---|
| **必消费** | 只要那次攻击命中（任一目标）就消费，不管效果是否产生位移 | 炽核熔炉、淬火槽、硫磺脉、电弧熔渣 |
| **出手结算** | 出手时预留，结算后按结果决定消费或不消费 | 膛压炉心（未命中不消费） |
| **条件消费** | 前置条件不满足则不消费，机会留到下次 | 矿渣回旋（返程未命中不消费） |

工程注意：`consume` 是"取了就清"，需要新增 `hasReady(run,key)` 做**预判**，再在结算点 `consume`。别在出手时先 consume 再判断结果。

### 1.4 目标与边界统一口径

| 场景 | 口径 |
|---|---|
| Boss | **吃**全部熔铸效果（熔穿、淬裂、硫毒、连锁、碎渣）；Boss 护甲由脚本控制，可被熔穿削到不低于 0 |
| Boss 召唤物 / 小怪召唤 | **吃**全部效果（含熔穿）；击杀召唤物**算击杀**（膛压炉心返 2） |
| 未命中任何目标 | 不产生效果、**不消费 `ready`** |
| 多目标（连锁/碎渣/爆炸） | 每次强化普攻**只结算一次 `ready`**，不按目标数累加 |
| 衍生伤害（连锁、碎渣） | 标 `derived`：不再消费任何 `ready`、不触发紫金、不再派生下一层 |
| 目标在效果生效前死亡 | 熔穿/淬裂照常挂（无意义但无害），不额外消耗 |

### 1.5 目标选择

- 主目标 = 该次攻击的原目标（塔现有索敌逻辑，不改）；
- 连锁目标 = 除主目标外、距主目标 ≤ 范围、按距离升序取前 N；
- 若可用目标不足 N，按实际数量结算，**仍算一次完整触发**。

## 3 四项优先项（单独列，工程最常问）

### 3.1 熔铸炮返能（`ur_forge_cannon` 金）

1. **消费时机**：出手前只"预判"不消费；该发结算完成（所有命中/爆炸结算完）后再决定。
2. **结算顺序**：先看是否有命中 → 无命中＝返 0 且不消费；有命中且有任一目标 `hp<=0` → 返 2；有命中但全存活 → 返 1。
3. **上限**：`min(armoryEnergyMax('cannon'), energy + n)`，不加不减其它资源。
4. **不叠加**：一次出手一次结算，多目标不累加（防"炸 5 只召唤物返 10 能量"）。
5. **与免能耗的关系**：圣庭炮金在 `attacks.js:53` 消费"出手即免"，熔铸金在"结算后返"，两者因槽位绑定不会共存。

### 3.2 熔穿减甲（`ur_forge_fire` 金）

1. **数值**：−10 个百分点（不是 −10%），即 `armor − 0.10`，下限 0。
2. **不写回**：绝不修改 `e.armor` 本身，只在护甲结算时读 `armor − break`（写入会与熔壳的"表外加成"打架，且到期回滚难）。
3. **叠加**：同目标不叠层，只刷新 3 秒；多张火卡不存在（槽位绑定）。
4. **与熔壳**：同向相加。W60 熔岩普通 34% + 满熔壳 20% − 熔穿 10% = 44%。
5. **与无视护甲（百分比）**：顺序为「先百分比、后绝对」→ `max(0, armor × (1 − ignore) − break)`。举 W60 满熔壳 54% + 火金 50% 无视 + 熔穿 10%：`0.54×0.5 − 0.10 = 0.17`。
6. **与 `boo_tip`（回旋 3★ 无视 20%）**：同属 ignore 通道，取**较大值不叠乘**（`max(0.5, 0.2)`）。
7. **Boss**：吃，但 Boss 护甲不会低于 0；Boss 的"开甲/闭甲"脚本（如 `lava-ridge` 的 `openArmor`）优先，熔穿在其结果上减。

### 3.3 淬裂增伤（`ur_forge_ice` 金）

1. **类型**：受伤乘区（`v *= 1.08`），对**直接伤害、dot tick、连锁、碎渣**全部生效。
2. **不叠**：同目标只 1 层，再挂只刷新时长（不会出现 8%→16%）。
3. **与风痕合并**：同属"受伤乘区"，两者**加算**为 `1 + 0.08 + 0.08`；与其它乘区（真火、腐蚀、紫+15%）仍是乘算。
4. **与减甲**：互不影响（一个乘区、一个护甲通路），同时存在时都生效。
5. **Boss**：吃。**不受 `controlResist` 影响**（它不是控制）。

### 3.4 硫毒无视护甲（`ur_forge_poison` 金）

1. **基数固定**：施加瞬间取"该次命中的减甲前伤害"算好每 tick 值，之后 tick 恒定，**不随目标护甲/熔穿/淬裂变化而变**（可验证、不漂移）。
2. **跳过护甲**：该 dot 在 `damage.js:93` 处不乘护甲项（用 dot 条目上的 `ignoreArmor:true` 标记），其它 dot 照旧乘。
3. **受什么加成**：受毒紫 +12%（目标身上已有 dot 时，硫毒自身也算 dot，从第 2 tick 起自满足）、受淬裂 +8%（tick 时读目标当前状态）、受 `talentBonus.dot`。
4. **不受什么影响**：不受熔穿影响（已跳过护甲）、不转移、不与普通中毒/圣种毒素合并。
5. **时长与总伤**：4 秒，总伤害 = 基数 × 45%（每 tick 0.1125 × 基数）。
6. **Boss**：吃，且是熔岩 Boss（0.38 护甲）最高效的单卡来源。

## 5 需要工程反向确认的 4 个接口（我按现有代码写的，请落地时核对）

1. **`consume` 没有"预判"接口**：`runtime.js:59-64` 是取了就清。膛压炉心/矿渣回旋需要新增 `hasReady(run, key)` 只读判断。`attacks.js:53` 的圣庭炮金用 `consume` 是"出手即免"，与新卡不同，别混用。
2. **护甲公式要改结构**（`damage.js:93`）：从 `armor * (1 - ignore)` 改为 `max(0, armor * (1 - ignore) - break)`。`break=0` 时结果与现在完全一致，但**必须回归一局圣坛基线**确认数值没漂。
3. **dot 会逐 tick 调 `beforeDamage`**：淬裂/风痕/毒紫都会在每次 tick 重新判定，这是现状行为；因此"基数固定"（3.4-1）必须靠把 dps 写死在 dot 条目上实现，不能在 tick 里重算。
4. **`enabled` 粒度**：现在 `purple/gold` 各有一个 `enabled`。熔铸 6 张一起打开时，若想灰度，可先只开 `gold`、`purple` 仍 false——但两者是同一张卡的两个档，建议**整卡一起开**，避免"2★ 没效果、3★ 有效果"的错乱。
