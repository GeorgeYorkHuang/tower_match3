## 4. 明度阶梯

| 层级 | L 区间 | 用途 |
|---|---|---|
| 高光 | 80–100 | 文字高光、宝石内高光点（小面积） |
| 主体亮面 | 60–72 | 宝石色 / 塔色受光面 |
| 主体中间调 | 45–60 | 怪物固有色 |
| 主体暗部 | 25–40 | 统一收进紫黑 |
| 背景 | 10–15 | 面板与战场底色 |
| 描边 / 阴影 | 5–10 | 全部轮廓 `#0e0b14` |

验证方法：成品转灰度，主体与背景仍可分即合格；接触表（sheet）缩略图测试为固定验收动作。

## 5. 禁忌清单（对应具体失败表现）

1. **不写实解剖** → 失败表现：怪物出现真实肌肉/比例，与 Q 版棋盘 gem 同屏即拼凑。
2. **不做像素风** → 与 canvas 矢量 UI 质感冲突。
3. **不用大面积渐变光晕** → 失败表现：背景被光晕洗成中灰，明度阶梯崩塌（特效层内 ≤ 15% 画面占比可豁免）。
4. **不模仿受保护 IP**（如某消消乐动物脸、某塔防植物）→ 版权红线。
5. **不用灰调冷色做主体** → 失败表现：暗底上灰怪物缩略图直接消失。

## 6. 一致性检查落法

| 检查 | 本项目具体动作 |
|---|---|
| 同族比对 | 四大战场怪物各排一张接触表：统一描边 6px / 二头身 / 各自战场辅色，只换主色 |
| 同对象状态比对 | 怪物常态 / 受击 / 死亡三态并排：光照方向与描边不变，只变表情与姿态 |
| 跨类别比对 | 怪物 + 宝石 + UI 图标 + 特效同屏：特效明度不得超过 UI 金，图标不得比怪物抢眼 |

### 10.3 风险说明（为什么必须换）

1. **跨机型不一致**：微信小游戏 canvas 的 emoji 走系统字体，iOS / 安卓 / PC 外观各异，低端机可能渲染成豆腐块——同一界面三种长相，直接违反风格一致性原则。
2. **色彩失控**：emoji 自带 Apple/Google 配色，不受 TOWER_HEX 与暗金 UI 约束，是当前「拼凑感」的最大来源。
3. **尺寸受限**：emoji 只有字号可调，无法做多状态（常态/升星/禁用）、九宫格与图集合批。
