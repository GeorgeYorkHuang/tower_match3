# 大图集无损优化与图片引用缓存

日期：2026-11-09。落实逐帧裁空、透明/重复帧共用、清理多余预加载与缓存三项；未降低分辨率、帧率或特效时长。

共保留517个逻辑帧，其中22个全透明帧不分配实际像素，4个完全相同的非空帧共用像素区域。逻辑帧数量、播放索引、fps、duration、pivot及伤害半径均未改变。PNG磁盘文件合计1615.0KiB → 1585.9KiB。

逐帧边界保留一圈原始透明像素，图集中再加2像素隔离边，防止采样相邻帧。直接复制RGBA，避免透明合成中的颜色舍入；调色板编码只有在逐像素解码验证完全一致后才采用。

## 播放接入

- 帧表原来的x/y/w/h保留为虚拟帧，packed记录新图集坐标、尺寸和相对偏移。js/game/atlas-frame.js把裁下来的区域按原缩放比例放回原位置，支持非等比拉伸、旋转及父级透明度。
- js/game/render.js的drawImg统一处理packed和empty帧。空帧仅跳过绘制，仍会准备该效果后续需要的图片，因此不会在第一张可见帧才开始加载。
- 火柱改用显式裁帧表；燃烧地面改用显式裁帧表。火雨、雷击、毒雾、毒池、火环沿用原时间/锚点入口。
- 删除火系模块创建时的旧火环预加载；火柱仅在实际播放时加载。原备份在assets_bk/atlas-optimization-20261109，不进入assets分包。

## 图片缓存

- 新入口：js/game/image-cache.js。主渲染每帧登记menu:分页或battle:地图；三选一/暂停等战斗弹层仍属于同一战场，不会因此清掉战斗图片。
- 切页后给2帧复用宽限，仍使用的公共图片保留，其他图片引用在清理时解除。20秒未使用的引用周期回收。
- 默认64MiB为引用缓存软预算；只回收近期未使用的条目，活跃图片不会为追求限额反复淘汰和重载。软预算不覆盖离屏画布、音频或其他模块持有的引用，也不等于手机总显存上限。
- 不清空图片src；解除缓存引用后由微信引擎按自身时机释放底层资源。被其他模块持有的图片继续有效。
- 已淘汰请求的延迟onload回调不能重新写回缓存，不能覆盖同URL新请求。加载错误保留原回退行为。
- 配置：js/config/performance.js的imageCache。诊断：GameGlobal.game.renderer.imageCacheStats()。

## 验证

- 七张图集全部517帧重建原逻辑画面：alpha逐字节一致，所有非透明RGBA逐字节一致；4种等比/非等比缩放下偏移与尺寸一致。
- 原fps、duration、pivot等元数据不变；全部实际drawImg入口验证通过。
- 缓存验证包括跨页、公共图复用、活跃图保护、预算回收、闲置过期、错误回退、旧请求晚回调及清空。
- 启动与五分页、燃烧来源和半径、毒池、炮台、激活时序、Combo×3、四连底框、圣遗物图标、状态合成预算回归通过。
- 真机温度和GPU实际驻留峰值仍需在同一手机、同一倍速下复测20波以后。
