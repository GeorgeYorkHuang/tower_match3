# R15第四批：公共状态工具拆分

## 接口与所有权

新增`js/combat/statuses.js`，每次显式接收Combat和Enemy，既有Combat接口保留委托：dotBoost、applyBurn、applyPoison、poisonStack、applyBleed、applySlow、freezeE；hasDot(e,type)为无上下文查询。

`tickBaseStatus(combat, enemy, dt)`提取原tickStatus前半段：增伤/控制窗口衰减、冻结事件、腐化移动真伤、DoT及结束爆发、标记/控制到期和移动流血。Combat.tickStatus先调用此函数，再执行原有瘟疫传染、毒藤缠绕与瘴气技能行为。

Enemy拥有dots、slow、frozen、bleed及相关层数/计时字段；Run拥有城墙回血与塔能量；配置仅共享定义。无模块级玩家、敌人或计时缓存。initEnemyState与主update的缺字段补齐仍在Combat，不复制第二套初始化。伤害、爆炸、特效和死亡回调继续走Combat公共入口。

## 迁移保持的原行为

- 灼烧首次施加与重复叠层的dps/上限/持续时间计算原样；赤印与燃尽仍按原顺序判定，先触发可能重置层数，不更改互相影响。
- 中毒重复施加仍取较高单层DPS、较长持续时间并更新频率/上限；src保留首次写入规则。poisonStack无毒时仍回退1。
- 流血仍不进入dots，按向下移动距离结算；重施重置距离和起点。hasDot只查dots，不顺手增加流血识别。
- 减速刷新、Boss冻结时长、寒髓返能及能量上限保持原逻辑；冻结事件与freezeE两条既有处理路径不合并。
- tickBaseStatus先扣DoT ttl，过期先结算余烬后移除；存活DoT每次调用至多跳一次，dt较大不新增补跳。tickI/freq现有读取方式保留。
- 腐化真伤保持直接扣血、置_dying/毒塔击杀计数/回调的原路径，不改走带护甲的damage。控制衰减仍可能减到负值，不额外钳制。
- 不调整DoT乘区或历史跨技能影响，不执行P2/P3，不引入新的debuff反应。
