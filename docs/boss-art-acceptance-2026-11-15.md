# 熔岩/霜风 W40、W60 Boss 美工验收结果

日期：2026-11-15。结论：概念方向可继续采用，正式运行时资源验收不通过，需返修后复验。本次未接入或覆盖运行时资源。

## 核验范围与证据

已读设计稿与美工交付清单；全量扫描27张alpha后缀PNG的尺寸、alpha覆盖；目视检查四张待机图、卡洛斯压制/死亡图及斯卡尔冰封图；通过Edge深色背景实际合成排除查看器忽略alpha造成的误判。没有声称16套技能均已逐帧播放验收。

证据：art/boss_lava_frost_w40_w60/acceptance-pixel-audit.json；acceptance-preview.html 与 acceptance-preview.png。复现脚本：tools/_audit_boss_art.ps1、tools/_audit_boss_boundaries.ps1。

## 通过项

- 27张alpha后缀图均有真实透明像素，透明像素占48.23%–86.78%；深底合成抽查无棋盘背景。注意alpha=0区仍保留原始棋盘、水印等RGB，部分查看器会显示这些RGB，不能据此认定假透明。
- 四位Boss轮廓与地图主题基本对应：矿甲双生、霜灵双体、熔炉核心、冰喉风暴，无需腿部步态。
- 冰封独立破壳、熔核独立素材的拆层方向合理，具备继续制作基础。

## 阻塞正式接入的问题

### P1 四张待机图未满足等格安全边距

全部宣称1024×1024、3列2行，横格宽约341.33px。检测x=341/683两条内部格边界上alpha>128的像素数（两行合计）：

| 图集 | x=341 | x=683 |
|---|---:|---:|
| 卡洛斯idle | 301 | 385 |
| 维尔德idle | 63 | 34 |
| 伊格尼斯idle | 434 | 580 |
| 斯卡尔idle | 356 | 541 |

边界非透明只是风险指标；结合目视可见卡洛斯拳甲、伊格尼斯肩甲/锁链、斯卡尔冰刃跨越标称格界，直接等格播放会裁主体或混入邻帧。维尔德风带也需单格检查。1024不能被3整除本身可由运行时舍入解决，角色越格才是阻塞原因。

返修：每帧独立导出256×256或384×384，用统一主体比例/锚点并留至少8%透明安全边距；在不裁轮廓的前提下再合并。交分帧源图，禁止只裁整图等分来掩盖越格。

### P1 冰封图含完整示意塔，不能直接当纯特效层

w60-skar-freeze-3stage-v1-alpha.png 三格都烘焙了石塔。叠在实际塔位会出现第二座塔，无法通过简单裁框完整去除塔体而保留冰壳。需重交纯锁定/纯冰封/纯破壳层，保持塔体区域空透，附真实塔位叠加示意。交付清单第四节称无塔体，第六节又承认含示意塔，两者冲突。

### P1 帧格元数据与素材命名未统一

卡洛斯死亡表写2列3行，设计稿其他表写法混杂；维尔德/伊格尼斯死亡在设计稿写横排，交付表写3列2行；斯卡尔shadowfission名字6f但表写5帧。必须逐资源交manifest，明确columns、rows、frames、播放顺序、逐帧源矩形和锚点，不能依赖文件名猜测。

### P2 待机帧动作与锚点缺少量化验收

四张idle为6帧而非任务要求8帧。6帧可以作为候选，但不能以“运行时支持6帧”替代动作质量验收。目视可见伊格尼斯上排中帧整体较小/位置改变，无法支持仅1–2px漂移的声明。需逐格对齐并给首尾循环预览；不得靠整身缩放制造呼吸。

### P2 死亡/回复动作应分离

卡洛斯death前段角色下部在行界处出现平切，需补全轮廓/逐格重排。死亡崩塌结尾不应直接复用于仍存活分身的超时回复；回复需独立回光/回炉叠层，保留实体姿态。

### P2 文档与缺件状态校正

目录README仍称4张早期8帧草案、并声称技能未完成，交付稿又称28项可用；设计稿同时有维尔德dash已交与未交两种说法。统一索引，旧稿标废，保留单一当前版本。明确维尔德风蚀、伊格尼斯打断泄压、霜风霜影独立动作是复用哪份资源或仍缺。
