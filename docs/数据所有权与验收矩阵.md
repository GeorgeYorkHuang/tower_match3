## 五、事实登记（卡面指定三项 + 审计新发现，均不改规则）

1. **P2/P3 口径**：P2 全局充能3★技能伤（`chargeSkillBoost`）仅 `isSkill=true` 生效（shotDmg 七乘区第4区）；P3 协同「重炮×大火球」explode ×1.5。定位与口径详见《数值字典-火冰.md》§1/§3-P3。R14 圣遗物触发迁移时以字典口径为准。
2. **宝箱碎片未入账**：`openDeepChest` 计算并返回 `gain.shards`（deep-chests.js:31，弹窗展示），但**从不写入 `meta.shards`**（:43-45 只入账 gold/diamond/stone；卡注入的 5 片除外）。玩家看到的碎片收益与实际资产不符。修复需拍板「无主碎片如何归属稀有度」，不在本卡范围。
3. **速开费用三源**：① `DEPTH_CHEST.tiers[].speedDiamond`（config.js:113-117，**0 读取点，死配置**，审计脚本 §E 可复现）；② 服务端公式 `Math.ceil(remainMin/60*4)`（deep-chests.js:54）；③ UI 同公式重复实现（menu-actions.js:264）。两处公式现等值，改费率需同步两处并清理死配置。
4. **R08 进度核对（供 Codex 参考）**：`save/snapshot.js copySaveData` 已在 **load 出口**深拷贝（存储快照与 Meta 已隔离）；剩余风险 = `Meta.fromJSON` 对**同一 saveData 对象**恢复两个 Meta 时共享 17 个引用键（审计 §A 清单：relics/relicLevels/relicStars/shards/runCodex/milestones/deepChests 之外的标量键无风险；`deepChests` 为 slice 浅拷贝，元素对象仍共享）。
5. **towerUnlocks 死字段**：无写点、fromJSON 强制 `[]`（meta.js:259），toJSON 透传仅为兼容；可在 R08 一并评估删除。
6. **`CONFIG.SAVE.fields` 旧口径**（config.js:184-187，列 gold/towerUnlocks/towerGlobalLevel/lastTs）与现行 v5 存档不符（v5 为 Meta 全量 toJSON），且 `towerGlobalLevel/lastTs` 在 v5 中不存在——纯文档性残留，无消费点。
