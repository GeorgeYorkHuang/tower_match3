# R15第五批：火塔攻击与命中拆分

## 模块与调用方式

新增`js/combat/towers/fire.js`，七个函数以Combat作为第一个显式参数，其他参数保持不变：

| 函数 | 职责 |
|---|---|
| _attackFireOnHit | 焰雨3★逐目标命中计数与三连真实弹道 |
| _fireAttackOnAttack | 普攻级熔炉计数/免费火柱入队、火焰弹射与返能回调 |
| hitFire | 单发火球的命中挂点与伤害段顺序 |
| _fireMultiShot | 多重火球中心弹、侧弹及各自的命中/分裂/大火球溅射回调 |
| _fireAttackHit | 单发火球命中伤害、焰雨追加火球与单发大火球入口 |
| _fireSingleBlast | 大火球范围溅射、概率点燃及爆核边缘效果 |
| _fireImpact | 焰雨三连/追加火球的伤害、debuff、分裂与爆炸 |

Combat同名方法保留薄委托；闭包捕获当前Combat和本次伤害快照，经既有公共方法调用。无模块级Run、敌人、塔、弹道或计数缓存。数值仍读取config/tower-skills与config；未复制配置表。

## 本批边界

attackOnce仍负责跨塔选目标、耗能、齐射、攻击调度和发射分流。hit仍负责电磁场跨塔触发、命中计数与通用表现；tryAttackDebuff仍统一判定debuff。公共伤害/弹道/状态与圣遗物死亡钩子保持原入口。

tickFire及火柱/火墙/火雨周期调度仍留Combat；本批只迁普攻级熔炉免费火柱的原入队代码，不移动落点结算或修改延迟。原注释与实际倍率的历史差异也不在本轮改动范围。applyBurn继续走公共状态模块。

保留所有原触发顺序与重复调用次数：熔炉/弹射每次普攻只判一次；焰雨在每条对应弹道命中时计数；多重火球替代普通火球；中心弹、侧弹和分裂子弹各自结算；子弹首碰移除不穿透。不合并_fireImpact与多重火球strike的相似代码，避免改变上下文伤害与回调顺序。

## 验证

`tools/_test_fire_attacks_split.cjs`固定读取7b14718完整旧Combat，不以当前薄委托作为旧实现：

- 1024组：7个迁移入口及attackOnce，覆盖大火球/多重火球有无、分支0~3、圣遗物0~3★、两组随机种子。
- 不只对比发射结果：推进初始弹道并执行后续子弹回调，比较伤害/debuff/特效调用、Enemy状态、Run计数与塔能量、弹道/表现参数、免费火柱队列及随机调用次数。
- 对通过addProjectile登记的弹道，验证visual与projectile关联；保留原普通单发路径不同的登记形态，不趁重构改写它。
- 额外断言：多重火球没有额外普通弹、一次攻击只扣一次能量/记一次熔炉计数、主目标死亡不影响侧弹、三次命中后下次三连、分裂首碰消失、两Combat实例隔离。

旧`_test_fire_rain3.mjs`用正则截取combat源码的方法体，薄委托后会截到后续方法而解析失败；本批移除该解析和临时全局CONFIG，改为调用真实Combat兼容入口，原三项行为断言不变，均通过。

相关回归通过：状态432组、伤害882组、弹道456组、火冰多弹道/延迟发射、焰雨3★、击杀1370组、波次554组与撤离检查点11项。没有调整技能UI旧用例或并行美术资产；这些不属于本批已验证范围。

本模块不由Renderer加载，不新增HTML绘制预览依赖；无需额外包或安装。

## 用户设备抽查

1. 多重火球替代普通火球；中心弹命中或目标死亡后，侧弹仍独立命中。
2. 多重火球C的分裂弹碰怪即消失，大火球溅射/边缘点燃正常。
3. 焰雨三连、火焰弹射返能与熔炉每五次免费火柱正常，不额外扣能量。
