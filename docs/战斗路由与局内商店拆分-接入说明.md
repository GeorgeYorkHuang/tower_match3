# R13 战斗路由与局内商店拆分

## 接口与边界

- `input/battle-actions.js` 导出 `dispatchTouch(game, point, version)`，返回原有的已消费布尔值。每次显式接收game，不缓存玩家/对局；菜单分支仍委托onMenuTap。设置面板使用传入版本号，避免反向依赖main。
- `screens/battle-shop.js` 导出 `createBattleShop({drawImg, IMG_SRC, fmtNum})`，其battleShop(ctx, state)在打开时返回shopPanelRect/shopItemRects/shopCloseRect；关闭时不绘制。Renderer兼容入口保留原字段和原有关闭状态下的矩形保留行为。
- 购买仍调用Main.buyStoreItem，扣局内Run.gold与更新Run.store；局外Meta金币/钻石不参与。现有Run.buyStoreItem与Main购买方法本批不合并。
- 塔详情/技能详情的点击路由已迁；它们的绘制与buildTowerSkillInfo仍留原处。本批没有修改商品、价格、强化数值、游戏状态机或手势生命周期。

## 路由顺序

本局圣遗物详情 → 主菜单 → 塔技能详情 → 塔详情 → 底部功能弹层 → 局内商店 → 倍速 → 功能按钮 → 当前战斗/测试/技能三选一/圣遗物三选一/结算/撤离状态。

弹层空白继续消费触摸；点外关闭也消费本次触摸。商店按索引只调用一次购买。结算首点跳过演出、第二点操作按钮的行为保留。
