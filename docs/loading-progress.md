# 启动加载进度与失败提示

日期：2026-11-09。

## 原问题

- 原来每100ms人为增加4%，88%后的下一次更新变成92%，超过注释中计划的90%上限。它不代表真实下载量。
- 原来无论是否继续下载，15秒后都显示加载失败；旧超时回调没有请求代号，可能干扰下一次重试。
- 素材包success后先显示100%，随后才require游戏主体。程序初始化或首帧失败，与下载失败混在一起。

## 当前流程

1. 素材包加载阶段只显示LoadSubpackageTask.onProgressUpdate实际提供的百分比。没有回调时显示等待动画，不编造百分比。
2. 上报100%后仍等素材包success，不以百分比代替加载完成信号。
3. 素材包success后显示「正在启动游戏／初始化中」，初始化阶段不编造百分比。
4. 主循环完成第一次update、render和原有自检后，通知boot.js结束加载流程；不再用加载画面覆盖已渲染的游戏。

15秒未收到更高的下载进度，只提示加载较慢；60秒无进展，允许用户主动重试，仍继续接收本次请求成功回调。只有平台真实fail、同步启动异常或首帧异常才显示失败。真实错误按「素材包加载失败」与「游戏启动失败」分别记录到控制台。

每次重试使用新的请求代号，旧请求的进度、成功和失败回调不能修改新状态。已下载的素材包在启动重试时复用。首帧失败后暂停该实例循环，重试复用原实例，避免重复注册触摸和创建音频；失败页触摸不穿透到旧游戏界面。首帧成功之后的普通帧错误继续沿用原游戏恢复循环。

## 验证

- 真实88%等待期间不会自动变成92%；真实上报92%仍正确显示92%。
- 负数/越界/NaN/回退进度、无回调、缓存命中、15秒慢加载、60秒无进展、晚到成功与重复回调。
- 失败与停滞重试、旧超时/回调隔离、缺失平台API、require异常、首帧异常、缓存包启动重试、计时器清理。
- 从真实loading.js进入实际GameMain，制造首帧绘制异常后重试成功；确认同一实例、触摸监听数量不增加、错误页使用物理像素坐标、成功后不再覆盖游戏。

此修复解决假进度与固定超时误判，不把真实平台错误当作成功。尚未取得用户真机上的原始errMsg，不能据此断言原先所有失败均由超时造成。
