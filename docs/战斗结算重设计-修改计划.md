## 二、关键结论：碎片从「即时入账」改为「局末入账」

这是第 1 条和第 5 条共同倒逼出的架构变动，**必须先做**，否则后面全是补丁。

**现状**：碎片在击杀瞬间 `meta.addShard` 直接入账（`main.js:807`），且 `addShard` 里内置了「达阈值自动解锁」（`meta.js:62`）。

**问题**：
- 已入账的碎片无法在局末按 30% 折扣收回（要么做减法，要么产生中间态不一致）
- 自动解锁与「玩家可选择不解锁」直接冲突

**改造**：碎片走「局内记账 → 局末结算 → 批量入账」

```
击杀掉碎片 ──→ runShardDetail[id] += n（只记账，不入账）
                ↓
重复圣遗物折算 ─→ runShardDetail[id] += n（同上）
                ↓
宝箱全解锁折算 ─→ runShardDetail[id] += n（同上）
                ↓
            局末 finishRun()
                ↓
     K = floor(总张数 × (撤离 ? 1 : 0.3))
                ↓
     从明细池按「张」等概率抽 K 张 → finalDetail
                ↓
     finalDetail 逐 id 调 meta.addShard(id, n)   ← 只加碎片，不自动解锁
```

### 抽样算法（按张等概率）

```js
// 展开成张数组 → Fisher-Yates 洗牌 → 取前 K 张 → 重新计数
const pool = [];
Object.keys(detail).forEach((id) => { for (let i = 0; i < detail[id]; i++) pool.push(id); });
const K = Math.floor(pool.length * ratio);
for (let i = pool.length - 1; i > 0; i--) { const j = Math.floor(Math.random() * (i + 1)); [pool[i], pool[j]] = [pool[j], pool[i]]; }
const finalDetail = {};
pool.slice(0, K).forEach((id) => { finalDetail[id] = (finalDetail[id] || 0) + 1; });
```

例：a×4 + b×3 + c×2 = 9 张，K=2 → 可能保留 a×2、a+b、b+c 等任意组合。

### 折算对照表

| 掉落总张数 | 保留 | 损失 |
|---|---|---|
| 10 | 3 | 7 |
| 9 | 2 | 7 |
| 8 | 2 | 6 |
| 4 | 1 | 3 |
| 3 | 0 | 3 |
| 1~2 | 0 | 全部 |

> 3 张及以下全损，体验很硬。结算页必须显式写「本局掉落 9 · 按 30% 保留 2 · 损失 7」，不能静默消失。

### 中途退出必须保底

`goMenu()`（`main.js:737`）和设置面板「重新开始」都可在战斗中途调用。碎片改为延迟入账后，中途退出会**凭空丢失**（现状是即时入账所以不会丢）。

**对策**：抽出 `settleRunShards(ratio)`，在以下三处调用：

| 调用点 | ratio | 说明 |
|---|---|---|
| `finishRun(evacuated)` | `evacuated ? 1 : 0.3` | 正常结算 |
| `goMenu()` 开头 | `0.3` | 中途退出视同失守 |
| `restart()` 开头 | `0.3` | 中途重开视同失守 |

> 不退化为 0，避免玩家觉得碎片被吞。toast 提示「中途退出 · 碎片按 30% 结算」。

### 3.3 ⚠️ 经济曲线连带影响（需你确认）

解锁开始消耗碎片后，单个金圣遗物的碎片消耗变成：

| 阶段 | 旧（自动解锁不扣碎片） | 新（解锁扣 8 张） |
|---|---|---|
| 解锁 | 8 张触发，碎片保留 | 8 张，扣完归零 |
| 升 2★ | 再 10 张 | 再 10 张 |
| **0→2★ 合计** | **10 张** | **18 张** |

蓝（2+10=12）紫（4+10=14）同理上升。这直接踩到 README 待排期第 8 条「圣遗物 meta 成长节奏」。

两个走法（不阻塞开发，但要早定）：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 接受成长变慢 | 碎片价值提升，「继续攒」有意义；配合结算页碎片明细展示，玩家感知更清晰 |
| B | 把 `STAR_UP.cost[2].shards` 从 10 降到 4~6 | 保持总消耗接近旧值，但会削弱「解锁」的分量 |
