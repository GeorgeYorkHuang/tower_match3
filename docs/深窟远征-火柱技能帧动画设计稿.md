# 深窟远征 · 火柱技能 8 帧帧动画设计稿

> 交付人：游戏美术师　日期：2026-10-28　状态：**待评审，未生成图片、未改动代码**
> 上游：`docs/消消防线-美术风格提案.md`（风格锚点 v1）、`docs/深窟远征-火墙技能帧动画规格.md`（同体系前例）
> 本文只解决一件事：把火塔技能「火柱」的 2.4 秒演出做成 **8 帧序列帧**，并给出可直接复制的 prompt。

---

## 1. 结论摘要

| 项 | 方案 |
|---|---|
| 帧数 / 时长 | **8 帧，覆盖完整 2.4 秒**（一次性演出，非循环） |
| 时间组织 | **关键帧时间轴**（8 个关键姿势，各帧停留 0.23~0.43s），不是等间隔 8fps |
| 交付画幅 | **256×512 透明 PNG × 8**（2 的幂，比例 0.5） |
| 游戏内绘制 | 200×400 逻辑 px，底边中心对齐落点 `(f.x, f.y)` |
| 地面标记 | **不画进贴图**，继续由代码绘制（精确对齐伤害半径 R=120~192） |
| 混合方式 | 主体 `source-over`（保描边与暗红底色）＋ 可选 45% `lighter` 辉光层 |
| 包体 | 8 帧约 320 KB |

**一句话设计**：火柱是一次性技能，演出应该像「一根火柱砸进战场」有起承转合，而不是一段可以循环的火焰纹理。所以 8 帧讲一个完整故事，且**帧边界精确压在当前代码的三个阶段分界上**（0.6s / 1.68s / 1.97s），接入时不必改动画时间逻辑。

## 2. 现状基线（从代码实测，不是猜的）

`js/game/render.js → fxPillar()`，`js/combat.js` 投放 `{ type:'pillar', r:120, dur:2.4 }`：

| 代码阶段 | 时间占比 | 时间 | 现绘制内容 |
|---|---|---|---|
| ① 地面火圈 | 0 ~ 25% | 0 ~ 0.60s | 双环扩张 + 圈上 10 颗火星 + 地面红晕 |
| ② 柱体升起 | 25% ~ 70% | 0.60 ~ 1.68s | 三层柱体（暗红/橙/黄芯），高 30→330，宽 16→66；顶部三簇火舌 + 6 颗上升火星 |
| ③ 白热冲击 | 70% ~ 82% | 1.68 ~ 1.97s | 黄白冲击环扩张 + 中心亮斑 |
| ④ 余烬消散 | 82% ~ 100% | 1.97 ~ 2.40s | 矮火苗 + 5 颗火星上升 |

数值事实：
- **伤害在 0.60s 结算**（`combat.js` 的 `pillarWaves: { t: 0.6 }`），动画与判定同帧；
- 柱体尺寸由 `r` 无关，固定 **高 330 / 宽 66**（逻辑 px，画布 750×1626）；
- 「燎原」分支只放大半径（120→144→168→192），**不改变柱体尺寸**。

## 3. 三个核心设计判断

### 判断一：8 帧是「一次性演出」，不是循环

火墙（持续 6s）适合 12fps 循环；火柱是 **2.4s 单次技能**，玩家一生只看一次——必须讲完整故事：**聚 → 燃 → 冲 → 顶 → 盛 → 摇 → 塌 → 烬**。

由此带来一个必须讲清的技术点：8 帧铺满 2.4s，平均 3.3fps，**低于 8fps 档位**。这不是违规，而是特效的「关键帧时间轴」——帧率档位约束的是**等间隔播放**的角色动画；特效由 timing chart 驱动，每帧停留时间本来就该按剧情分配（出手快、收招慢）。为规避异议，文档给出每条边界的精确毫秒，接代码时按表映射，不依赖"帧率"概念。

### 判断二：地面标记留给代码，贴图只做「柱」

三条理由：
1. **精度**：地面圈就是伤害范围，必须严格等于 R；贴图缩放会让线宽跟着变粗，R=192 时圈会糊成一团；
2. **透视**：战场是 45° 俯视，地面圈应该是**椭圆**，而火柱是**正面立视**——两种透视塞进一张图必然自相矛盾；
3. **分支联动**：燎原分支要放大圈，代码一个变量就够，贴图不用重出 8 帧。

> 这与火墙的既有做法一致（火墙=代码画地面红晕 + 贴图画墙体），是项目内已验证的模式。

### 判断三：帧边界压在代码阶段分界上

| 代码边界 | 时间 | 对应帧边界 |
|---|---|---|
| ①→② 柱体出现 | 0.60s | **F2 → F3** |
| ②→③ 白热冲击 | 1.68s | **F6 → F7** |
| ③→④ 余烬 | 1.968s | **F7 → F8** |

接入时 `fxPillar` 只需把「阶段内画什么」换成「按时间选哪张图」，四个阶段的时间常数一个都不用改，**动画与伤害判定天然继续对齐**。

## 4. 8 帧分镜（关键姿势 + 时间轴）

柱高以游戏内 330 逻辑 px 为 100%，宽度以 66 逻辑 px 为 100%。

| 帧 | 名称 | 停留 | 累计 | 柱高 | 柱宽 | 剪影特征（灰度可辨） | 叠加的代码层 |
|---|---|---|---:|---:|---:|---|---|
| **F1** | 聚·火种 | 0.32s | 0 ~ 0.32 | 8% | 20% | 只有地面一点竖直小火苗，画面空 | 地面圈扩张 + 10 火星 |
| **F2** | 燃·窜起 | 0.28s | 0.32 ~ 0.60 | 25% | 35% | 细长 S 形火舌，尖端分两叉 | 地面圈收口 |
| **F3** | 冲·出声 | 0.25s | 0.60 ~ 0.85 | 60% | 60% | 等宽直柱，顶部闭合圆头 | 无（伤害在 0.60s 结算） |
| **F4** | 顶·触天 | 0.25s | 0.85 ~ 1.10 | 100% | 85% | 顶部初分三尖，柱身笔直 | 无 |
| **F5** | 盛·绽放 | 0.32s | 1.10 ~ 1.42 | 100% | **100%** | 三簇大卷舌横向张开，比柱身宽 | 无（最亮帧） |
| **F6** | 摇·持稳 | 0.26s | 1.42 ~ 1.68 | 95% | 95% | **整体左倾约 15°**，冠部倒向一侧 | 无 |
| **F7** | 塌·崩解 | 0.29s | 1.68 ~ 1.97 | 55% | 110% | 顶部断裂成三个分离火团，柱身有白裂纹 | 白热冲击环（代码画） |
| **F8** | 烬·消散 | 0.43s | 1.97 ~ 2.40 | 15% | 45% | 只剩低矮火苗，火星上升渐隐 | 余烬火星（代码画） |

**三段节奏校验**（技能规范要求 预备 25–35% / 出手 10–20% / 收招 45–60%）：

| 段 | 帧 | 时长 | 占比 | 判定 |
|---|---|---:|---:|---|
| 预备 | F1–F2 | 0.60s | **25%** | ✓ |
| 出手 | F3–F4 | 0.50s | **21%** | ✓（略高于 20%，蓄势够快） |
| 收招 | F5–F8 | 1.30s | **54%** | ✓ |

**帧事件**（技能规范：攻击类必须标）：

| 接口 | 值 | 说明 |
|---|---|---|
| `hit_frame` | **0.60s**（F3 起始） | 与 `pillarWaves.t = 0.6` 对齐，伤害与柱体出现同帧 |
| `clamp` / `hold_last` | **clamp** | 末帧不驻留，2.40s 后特效对象直接移除 |
| `loop` | 无 | 非循环 |
| `sfx_frame` | 0.60s | 建议同时播 boom |

**白帧检查**：8 帧柱高序列 8%→25%→60%→100%→100%→95%→55%→15%，唯一两次同高是 F4/F5，但宽度 85%→100% 且冠部分叉形态不同，涂黑后宽度差 15% 仍可辨。**无白帧**。

## 5. 交付规格

| 项 | 值 | 说明 |
|---|---|---|
| 生成画幅 | 1024×1536 竖版 | 图像工具支持 `1024x1536` |
| 交付画幅 | **256×512** | 2 的幂；比例 0.5 与显示尺寸 200×400 严格等比 |
| 命名 | `anim_firepillar_01..08.png` | 对齐项目现有 `anim_firewall_01..04`；规范式 `anim_<对象>_<状态>_<帧>_v<N>` 留待全项目统一时一起改 |
| 透明底 | 是，四周留 2px 缓冲 | 防抽边 |
| 描边 | 生成图约 **12px @1024 宽** → 缩放后 ≈3px@256 → 显示 ≈2.3 逻辑px | 与游戏内描边同量级；不能照抄塔图标的 6px（缩到 256 会细成 1.5px） |
| 锚点 | 底边中心 = 落点 `(f.x, f.y)` | 与现有柱体绘制基准一致 |
| 游戏内尺寸 | 200×400 逻辑px | 柱体 330 + 冠部火舌约 70 |
| 色板 | `#c0392b` → `#ff7043` → `#ff9f43` → `#ffd24a` | 四层，与火塔 `#ff6b6b` 家族、火墙四帧同族 |
| 混合 | 主体 `source-over`；辉光层可选 45% `lighter` | 沿用火墙 v1.17.18 的实测结论：纯加法会把卡通描边和暗红冲白。**规范上属"混用"，但这是有实测依据的项目级既定偏离，同一特效只用同一组合** |
| 粒子峰值 | 代码层 10（地面圈）+ 6（柱身）= **16** | ≤ 40 单特效上限 |
| 同屏实例 | ≤ 2（实际每 10s 一次，同屏通常 1） | |
| 生命周期 | **2.40s** | 超出规范建议的 2s；因技能时长由战斗数值定死，采用「单次 8 帧」而非额外循环层控制开销 |
| 包体 | 8 × 约 40 KB ≈ **320 KB** | 分包 4.51 → 约 4.83 MB，总包仍在 30MB 内 |
| 遮挡 | 200×400 / (750×1626) ≈ **6.6%** 屏占比 | ≤ 30% 上限 |
| 闪光频率 | 2.4s 内 1 次（白热冲击） | < 3 次/秒 |

## 9. 待你拍板（5 件）

1. **演进式 vs 循环式**：现在是 8 帧讲完整故事（推荐）。若你希望"火柱维持期间更活"，可改成 F5/F6 两帧在 1.10~1.68s 内互换微循环——代价是 8 帧里少一帧可用于收招。
2. **柱体是否随「燎原」分支放大**：现方案柱体尺寸固定、只有地面圈随 R 变（推荐，避免缩放糊边）。若希望"范围变大时柱子也更粗"，我给柱体加 1.0→1.15 的轻缩放。
3. **交付分辨率**：256×512（约 320KB）还是 512×1024（约 800KB，更锐但分包重约 480KB）。
4. **F7 崩解与代码白热冲击环是否叠加**：同时出现可能过于拥挤，建议只留崩解（去掉冲击环代码），或只留冲击环（F7 改为纯崩塌无白光）。
5. **预警是否够**：现在是 0.6s 地面圈预警。火柱是 120% 伤害的 AOE，0.6s 是否偏短？若要 0.9s，我把 F1/F2 各延长 0.15s，总时长变 2.7s，需同步改 `dur`。
