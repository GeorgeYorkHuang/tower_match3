| 项 | 方案 |

**一句话设计**：火是一种**守恒的力**——先在地上画出一个圈（宣告范围），圈里的火被吸向中心拧成一根柱子，柱子冲天而起的同时把火从中心推向圆的边缘，到边即散，火走了但地烧焦了。8 帧就是这一条因果链，一帧不多。

## 2. 为什么 75° 会改变画法（先讲清透视，再谈美术）

俯角 75° 指相机从水平面抬高 75°，**接近正上方俯视**。两个投影系数是全部推导的起点：

| 方向 | 投影系数 | 75° 取值 | 后果 |
|---|---|---|---|
| 地面圆 → 屏幕椭圆短轴 | `sin θ` | **0.966** | 地面圆**几乎还是正圆**，只轻微压扁 |
| 竖直长度 → 屏幕高度 | `cos θ` | **0.259** | 柱子会被压到不足三成高 |

由此得到三条硬约束：

1. **火圈画成轻微椭圆**（短轴 = 长轴的 0.95），不是 45° 斜视那种明显扁椭圆。好处是它与代码里 `ctx.arc` 画的判定圆几乎重合，贴图与游戏逻辑**不会打架**。
2. **柱子必须夸张**。按真实透视，330 逻辑 px 的柱子只显示 85px，那是块矮墩。所以柱体高度按"游戏可读性"放大到视觉 ≈300px——这是特效的合法夸张，但**俯视特征必须画对**：柱顶要能看到火焰的**顶面**（带卷涡的亮斑/环），柱底与地面交界处要有一个**椭圆截面亮环**（火从地里冒出来的口）。少了这两个面，75° 就退化成正面立视了。
3. **火的扩散天然是"向上摊开"**。俯视时从中心往外铺的火，在屏幕上表现为**绕落点向外膨胀的一圈环带**，不是向屏幕两侧横飞。分镜里所有"扩散"都按这个规律画。

## 3. 现状基线（代码实测，不是猜的）

`js/game/render.js → fxPillar()`，`js/combat.js` 投放 `{ type:'pillar', r:120~192, dur:2.4 }`：

| 代码阶段 | 时间 | 现绘制内容 |
|---|---|---|
| ① 地面火圈 | 0 ~ 0.60s | 双环扩张 + 圈上 10 颗火星 + 地面红晕 |
| ② 柱体升起 | 0.60 ~ 1.68s | 三层柱体（暗红/橙/黄芯），高 30→330，宽 16→`R·0.42`；顶部三簇火舌 + 6 颗上升火星 |
| ③ 白热冲击 | 1.68 ~ 1.97s | 黄白冲击环扩张 + 中心亮斑 |
| ④ 余烬消散 | 1.97 ~ 2.40s | 矮火苗 + 5 颗火星上升 |

事实：**伤害在 0.60s 结算**（`pillarWaves { t: 0.6 }`），与柱体出现同帧；柱宽随 `R` 变（`16 + k·R·0.42`），柱高固定 330；「燎原」只放大 `R`。

## 4. 8 帧分镜

圈半径以伤害半径 `R` 为 100%，柱高以游戏内 330 逻辑 px 为 100%。

| 帧 | 名称 | 停留 | 累计 | 火圈半径 | 柱高 | 剪影特征（灰度可辨） | 说明 |
|---|---|---:|---|---:|---:|---|---|
| **F1** | 圈·落印 | 0.18s | 0.00–0.18 | 0 → 100% | 0 | 只有地面一个椭圆火环 + 环上 12 簇小火苗，中心一个亮点，其余全空 | 环从中心炸开到满径，宣告范围 |
| **F2** | 聚·收束 | 0.42s | 0.18–0.60 | 100% → 52% | 0 → 12% | 环缩至一半，环上火苗**朝内倒伏成流线**，火星从环飞向中心，中心凝出小火种 | 核心帧：火被"吸"进去 |
| **F3** | 生·立柱 | 0.18s | **0.60**–0.78 | 52% → 42% | 12% → 30% | 中心立起细直小火柱，火圈贴地收成薄环 | **爆发点，与伤害结算同帧** |
| **F4** | 冲·拔高 | 0.30s | 0.78–1.08 | 42% 薄环 | 30% → 72% | 柱体笔直拔高，三层色带，顶部仍闭合圆头 | 只有柱，圈几乎不可见 |
| **F5** | 顶·满高 | 0.28s | 1.08–1.36 | 42% → 58% | 72% → 100% | 柱顶分三舌，柱底**出现外溢的火焰裙**（第一次扩散） | 亮度峰值，**柱体形态基准帧** |
| **F6** | 扩·抵边 | 0.32s | 1.36–**1.68** | 58% → 100% | 100% → 94% | 柱体上段开始松散，火**同时推到最外围**，外圈连成完整燃烧带 | **外圈形态基准帧** |
| **F7** | 散·崩解 | 0.29s | 1.68–**1.97** | 100%，断裂 | 94% → 35% | 柱体碎成 4–5 团分离火球向外上方飞散，外圈变薄、边缘出现缺口 | 崩解与消散同时 |
| **F8** | 烬·余痕 | 0.43s | 1.97–2.40 | 100%，熄 | 0 | **无火柱**，地面剩暗红余烬裂纹网 + 焦痕 + 十余点将熄火星 | 停在结束，接地面 DoT |

### 4.1 三段节奏校验（规范：预备 25–35% / 出手 10–20% / 收招 45–60%）

| 段 | 帧 | 时长 | 占比 | 判定 |
|---|---|---:|---:|---|
| 预备（圈 + 汇聚） | F1–F2 | 0.60s | **25%** | ✓ |
| 出手（立柱 + 拔高） | F3–F4 | 0.48s | **20%** | ✓ |
| 收招（满高 + 抵边 + 崩解 + 余烬） | F5–F8 | 1.32s | **55%** | ✓ |

### 4.2 白帧检查

柱高序列 0 → 12 → 30 → 72 → 100 → 94 → 35 → 0；火圈半径 100 → 52 → 42 → 42 → 58 → 100 → 100 → 100。
唯一"同高"是 F6/F7（94% vs 35%，差 59 个点）与 F7/F8（35% vs 0）。**按剪影（涂黑）逐对比较均可辨，无白帧**。

### 4.3 帧事件

| 接口 | 值 | 说明 |
|---|---|---|
| `hit_frame` | **0.60s**（F3 首帧） | 与 `pillarWaves.t = 0.6` 对齐 |
| `sfx_frame` | 0.60s | 建议同帧播 boom，F1 播预警轻响 |
| `loop` | 无 | 一次性 |
| 末帧处理 | `clamp` 到 2.40s 后移除对象 | F8 之后地面余烬交给 `groundDots` 续画（C 分支 3 秒 DoT） |

## 5. 交付规格

| 项 | 值 | 依据 |
|---|---|---|
| 生成画幅 | 1024×1280 竖版 | 与 512×640 同比 |
| 交付画幅 | **512×640** | 显示宽 = `2R×1.10`；`264 × (640/512) = 330`，**正好还原现有柱高 330**，接入零调参 |
| 命名 | `anim_firepillar_01..08.png` | 对齐 `anim_firewall_01..04` |
| 透明底 | 是，四周留 4px 缓冲 | 防火圈被裁 |
| 描边 | 生成图 **10px @1024 宽** → 交付 ≈5px → 显示 ≈2.5 逻辑px | 与塔/怪物同量级，不能照抄塔图的 6px |
| 锚点 | 底边中心偏上：**落点在画幅 y = 640×0.78 处**（下方 22% 留给火圈下半） | 火圈圆心即落点，必须可算 |
| 显示尺寸 | 宽 `clamp(2R×1.10)`；R=120 → 264×330，R=192 → 422×528 | 屏占比 18.3%（< 30% 上限） |
| 色板 | `#c0392b` → `#ff7043` → `#ff9f43` → `#ffd24a`；余烬用 `#7b241c` + `#c0392b` | 火塔 `#ff6b6b` 同族 |
| 混合 | 主体 `source-over`；辉光层 45% `lighter` | 纯加法会把卡通描边和暗红冲白（火墙 v1.17.18 实测） |
| 粒子 | 代码层 10（圈）× 6（柱）= 16，≤ 40 | 贴图自带火星不计入 |
| 包体 | 8 × 约 200 KB ≈ **1.6 MB** | 分包 4.51 → 6.1 MB |

## 9. 待你拍板（3 件）

1. **火圈进贴图**——我改成进贴图了（你描述的"汇聚"只能靠贴图画流线，代码圆环画不出被吸的感觉）。代价是贴图变大（1.6 MB），并且代码要保留一条细判定环。**如果你更想省包体，可退回"代码画圈 + 贴图只画柱"，但汇聚感会弱一半。**
2. **交付分辨率**：512×640（1.6 MB，推荐）vs 384×480（约 0.9 MB，略软）。
3. **F7 崩解是否保留代码的白热冲击环**：建议**删掉**（崩解已是满屏白光，重复）。

预警 0.6s 我按不动处理——`pillarWaves.t = 0.6` 写死在 `combat.js`，改时长会牵动数值与手感，美工侧硬压对齐更安全。若你确实觉得太短，我再单独提一条数值改动。

## 10. 假设清单

- 火柱仍是一次性技能，不做持续型改造。
- 燎原分支只放大整体（圈 + 柱同比），不做"柱体固定、只放大圈"。
- F8 之后的地面余烬由 `groundDots` 接手，贴图不驻留。
- 8 帧为交付上限，不加插值帧；若实机偏顿（3.3fps），用帧间 0.08s 交叉淡化改善。
