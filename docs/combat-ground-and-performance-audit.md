# 燃烧地面位置、范围与第二轮战斗性能核对

日期：2026-11-09。范围为真实战斗代码及当前工作区；未修改战斗平衡数值。

## 燃烧来源逐项核对

下表圆形范围都是游戏逻辑坐标中的**半径**，不是贴图边长或直径。渲染以实体的 `x/y/r` 为准。

| 来源 | 圆心/位置 | 实际半径 | 持续时间 |
|---|---|---|---|
| 多重火球 C 散射 | 每枚主火球命中的怪物位置 | 40 | 1.5/2/2.5秒 |
| 火柱 C 余烬 | 该次火柱记录的命中落点 | B0/1/2/3为120/144/168/192 | 3秒 |
| 灼烧 SSR 3星 | 灼烧怪物死亡的位置 | 60 | 3秒 |
| 碎裂弹 C 灼地 | 各枚碎裂子弹的引爆位置 | 80 | 1/2/3秒，加卡牌持续时间加成 |
| 炮火支援 C 焦土 | 该发炮弹实际落点；活目标使用预测位置 | 80×(1+炮系范围加成) | 2秒 |
| 炮火支援 SSR 3星 | 同一发炮弹实际落点 | 80×(1+炮系范围加成) | 3秒 |

炮系范围加成来自「溅射·余震」20%/35%/50%，以及「爆炸·威猛」3星25%；两张都3星时，炮火支援留地半径为140。碎裂弹的灼地直接读取碎裂弹地面实体的80，未因为共用贴图被改为其他半径。

「烈焰墙」保持独立矩形判定与渲染：220×45，B分支按1.2/1.4/1.6倍扩展，最高352×72；没有合并成圆形地面。「火雨」是多波落地范围伤害，目前不额外生成持续燃烧地面。旧火山留地函数仍是不可达兼容代码，当前火山触发函数为空，不算现役燃烧来源。

共享图集的参考半径100只用于计算 `scale = 实体半径 / 100`。锚点(128,150)映射到实体圆心；256×256是包含火苗高度和透明边缘的单帧尺寸，不能当作伤害范围。

### 修复的遗漏

炮火支援 SSR 留地使用 `key: 'cannon'`，此前地面绘制只认 `key: 'fire'` 或 `kind: 'cannonBurn'`，导致这块区域结算伤害但没有显示燃烧。本次已接入同一低开销动画，并且保留它自己的落点、半径、寿命。清理了旧灼地分支中已不可达的重复回退。

## 其他高开销及处理

1. **瘴气逐怪扫描全局特效**：技能未选时，每只怪物每帧都 `filter` 一次完整特效数组；技能已选时又逐怪 `some`。压力场景120怪、数百条特效会产生大量重复扫描和临时数组。改成每次战斗更新维护一次驻场条带，逐怪部分仅处理该怪的状态。
2. **风痕叠层**：原本每个风痕、每次怪物命中都查询卡牌，并在3星叠层分支遍历/分配整个风痕数组。卡牌条件改为本次风痕更新读取一次；范围比较改为平方距离；最多3层，找到另两个覆盖区即停止。未改变原来的逐区伤害顺序、到期移除顺序和层数规则。
3. **热路径反复查找模块**：伤害、状态、局内卡牌查询在高频函数中反复调用 `require`。将天赋运行时和退役ID表绑定到文件顶部，退役ID查询改用Set；没有缓存动态伤害、能量或星级结果。Node下这部分改善明显，微信运行时改善幅度需真机采样。
4. **持续区域逐怪开方**：圆形内部/边缘环比较使用平方距离，保留原半径和结算频率。
5. **短时粒子洪峰**：压力用例集中击杀时通用特效峰值超过1100条。新增每帧240个装饰粒子点的绘制预算，优先显示最新粒子。仅限制绘制，不删除特效事件，不少结算伤害，也不限制真实弹道、技能主体或怪物受击反馈。配置：`js/config/performance.js`。
6. **重开残留**：补清火柱延迟队列、火墙、火雨队列和对应视觉，避免旧目标引用及旧落点进入新局/测试切塔。

## 验证

- 使用真实生成函数检验11组来源/分支/范围加成组合，校验圆心、半径、寿命、图集缩放和裁帧；包含炮火支援预测落点、两种留地同时存在及到期不再绘制。
- 500条粒子和真实子弹混合绘制，粒子恰好限制240点，保留最新粒子；子弹全部绘制；小负载保持原显示数量；输入事件未修改。
- 两个独立进程分别读取改动前备份和当前源码，固定随机种子和时钟，在120怪、多技能分支压力构筑及集中击杀场景中比较。每模拟1秒保存一次敌人血量/状态、伤害统计、击杀、弹道、地面区域、风痕、特效时间线和随机数调用次数；四组结果全部一致。重开清理作为单独修复测试，不用旧残留当作正确行为。
- 这组测试使用画布适配器，不包含真实GPU绘制和手机温度，且高覆盖压力构筑不代表某一波玩家必然具备的配置。

| 真实逻辑压力场景 | 帧数 | 优化前桌面耗时 | 优化后桌面耗时 |
|---|---:|---:|---:|
| 火/毒/电/炮，120怪 | 1800 | 4742ms | 926ms |
| 火/冰/镖/炮，120怪 | 1800 | 10166ms | 1458ms |
| 瘴气构筑，120怪 | 600 | 770ms | 296ms |

各进程的JIT、GC及电脑负载不同，耗时仅作热点改善证据，不能换算成真机帧率提升比例。启动、毒池、炮台、Combo×3、四连图标、状态缓存预算回归已通过。

## 仍需真机采样的重点

- **图集解码内存**：文件压缩后小，不代表上传到纹理后小。按RGBA粗算，`fire-approved/meteor.png`约26.48MiB，`electric-approved/lightning-strike.png`约15.23MiB，火柱图集约13.84MiB，毒池约10.94MiB，预合成燃烧地面约10MiB；六系激活图集每张约7.5MiB。这里只是各图片的理论解码体积，不是实际同时驻留内存测量。建议下一轮针对这些图集做裁空、去重或分辨率分档，并验证视觉。
- **主画布高像素比填充**：当前仍按设备原始像素比绘制，没有降低分辨率或帧率；需要真机GPU/帧耗时数据后再决定省电选项。
- **真实弹道与大范围扫描**：链式技能部分路径仍有排序索敌，弹道/区域仍随实体量增加。此次保留了战斗对象和结算顺序；若后续真机采样仍指向这些路径，再实施空间索引或候选排序优化，并做同样的确定性对照。
